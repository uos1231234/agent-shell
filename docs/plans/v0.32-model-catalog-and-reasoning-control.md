## 1. 约束（Constraints）

这一段是 9 条约束。

1. **铁律**：不改 guard、上下文组装顺序、loop 主循环。shell 层仅允许两处**数据加法**：`src/protocol/client.ts` 的 `normalizeUsage`（解析 `completion_tokens_details.reasoning_tokens`）与 `src/shell/metrics.ts`（`Usage`/`Metrics` 加可选字段）——不改任何 guard 读取逻辑。
2. **thinking 缺省 'max' 保持不变**（v0.30 用户拍板 2026-09-09："只有能够完成任务才具备意义"）。本计划不改变默认策略，只增加运行时调节入口。
3. **档位词汇已锁定** `ThinkingEffort = 'max' | 'high' | 'low' | 'off'`（无 medium——DeepSeek 官方文档 medium 映射到 high）。[已验证] ARK 探针 2026-09-09：`reasoning_effort:'off'` 直发 400（两个模型都是）；`off` 的唯一正确 wire 编码 = `thinking:{type:'disabled'}`（现有 assembly requestExtras 已按此实现，零改动）。
4. **模型目录属服务商范畴 → 留在 providers.json**（v0.25 拍板：凭据/服务商在 `~/.agent-shell/`，功能配置在 `~/.databus/`）。
5. **gate 是唯一数据面**（v0.24 拍板）：前端不直读 providers.json，一切经 `provider.*` 命令。
6. **旧配置零迁移**：没有 `models[]` 的 providers.json 必须照常工作（单模型目录 + 内置能力表补齐）。
7. **gate 命令模式**：穷尽 switch 强制路由 + optional handlers（`provider.*` v0.23 先例，`845d101`）。
8. **[已验证] 模型能力差异是硬事实**（ARK 探针 2026-09-09）：`deepseek-v4-flash` 支持开/关 + effort 档位；`glm-5.3-flash` 是 always-thinking 模型（`thinking:{type:'disabled'}` → 400 "not supported by this model"），`reasoning_effort` 虽 200 但档位语义不可靠。能力元数据必须按模型声明，不能一刀切。
9. **commit 纪律**：逐 commit 编译验证（§6.7 教训：并行子代理交付后按依赖顺序验证 tsc）。

## 3. 架构信息（Architecture）

```
┌─ webapp 模型选择器 ─┐   ┌─ CLI /model /effort ─┐
│ (Composer 旁触发器)  │   │ (TUI 命令)            │
└─────────┬───────────┘   └──────────┬────────────┘
          │ provider.list / provider.select        │ 同左（gate 进程内）
          ▼                        ▼
┌─────────────────── Signal Gate ───────────────────┐
│  gate.command: provider.select {provider?,model?,effort?}
│  gate.emit:    provider.changed {catalog 快照}  ←─ 写盘成功后宿主 emit
└─────────┬─────────────────────────────────────────┘
          ▼
  宿主 handlers（assembly.ts）
  写 providers.json（磁盘唯一事实源：active / provider.model / provider.reasoningEffort）
          │
          ▼ 下一轮 runPrompt（既有热切换机制，零改动）
  resolveCurrentPlan() → resolveLLMPlan() → LLMPlan {
      model = provider.model                    ← 当前选中模型
      thinking = provider.thinking              ← 强制覆盖（旧字段，最高优先）
                 ?? provider.reasoningEffort    ← 新：用户选择的档位
                 ?? 模型 defaultEffort           ← 新：models[] 声明 ?? 内置表
                 ?? 'max'                       ← 终极缺省（v0.30 拍板不变）
      modelReasoning = 有效档位表（宿主解析好，前端不重复实现）
  }
          │
          ▼
  buildRequestExtras(plan)（既有，零改动）:
      off → {thinking:{type:'disabled'}}
      其余 → {thinking:{type:'enabled', reasoning_effort}} + max_tokens
          │
          ▼
  llm-adapter.ts（新增 400 自愈）→ call.ts fullRequest → ARK
```

**能力解析两级来源**（新增 `src/config/model-capabilities.ts`）：

| 来源 | 优先级 | 内容 |
|---|---|---|
| providers.json `models[].reasoning` | 高（用户显式声明） | 用户自填的 efforts/defaultEffort |
| 内置 KNOWN_MODELS 表 | 中（按模型名匹配，只收[已验证]条目） | `deepseek-v4*` → off/low/high/max, default max [已验证]；`glm-5*` → low/high/max（always-thinking 不可关）[已验证] |
| 未知且未声明 | 低（**保守：不注入**） | 不发任何 thinking/reasoning_effort 字段（AtomCode 白名单 + KimiCode 目录同款语义） |

**档位语义**（用户澄清 2026-09-09）：`max` = 最大思考；`high` = 官方默认的正常模式强度（dsh 的 defaultEffort=high 即此语义）——UI 文案须区分（如「高（官方默认）」/「最大」）。缺省档仍为 'max'（v0.30 拍板不变）。

**reasoning tokens 数据流**：ARK `usage.completion_tokens_details.reasoning_tokens` → `protocol/client.ts normalizeUsage` → `protocol Usage` → `shell metrics.addUsage` → `Metrics.reasoningTokens`（累计）→ turn.end → webapp LastResultRow「其中推理 N」。

## 4. 设计原则（Principles）

1. **磁盘是唯一选择事实源**：选择 = 写 providers.json（对齐 `/provider use` 既有语义，dsh 的 `agentDefaultModel.saveSelection` 同构）。不引入第二套会话级选择状态——那是 dsh 为其事件日志架构做的，我们的 `provider.changed` 快照广播已覆盖多客户端同步。
2. **UI 门控与 wire 编码同源**：有效档位表由宿主在 `provider.list` 回执里解析好（每个模型带 `efforts` + `defaultEffort`），前端只渲染不推导——UI 永远选不出模型不支持的档位（dsh `segmentsFor` 语义：不可关思考的模型不渲染"关"项）。
3. **切模型 = 档位跟随新模型默认**（dsh `choose({provider, model})` 不带 effort、服务端物化 defaultEffort 的同款语义）：`provider.select {model}` 时清除 `reasoningEffort` 字段，让解析链落到 defaultEffort。
4. **未知模型保守不注入（用户质询后修订，对齐三家）**：AtomCode（白名单启发式，未知不发字段）、KimiCode（能力目录，未知无能力）、dsh（发前校验抛错）三家对未知模型全部保守——乐观全档在严格网关上的失败模式（每轮 400 且错误格式不匹配自愈窄匹配 → 会话全废）不可接受。**修订**：未知且未声明 → 不注入任何思考字段；三条显式出口（`models[].reasoning` 声明 / `provider.thinking` 强制 / 内置表）；400 自愈保留但收窄为"已知/已声明模型的兜底"，窄匹配 400 错误消息中的字段名（ARK 格式 [已验证]）。
5. **热切换修复优先**：F1（streamChat 缓存键缺 extras）不修，前端调节按钮就是假的——切了不生效。这是本轮第一优先修复点。

## 7. 决策信息（Decisions）

**已定（历史拍板 + 本轮拍板，带理由）**：
1. dsh 式单 enum（用户拍板 2026-09-09 本轮）——`off/low/high/max`，off → `thinking:disabled`。与既有 `ThinkingEffort` 词汇完全一致，零迁移。
2. thinking 缺省 'max'（v0.30 用户拍板）——保持。档位语义澄清（本轮）：high = 官方默认正常强度，max = 最大思考，UI 文案区分。
3. 一体化一轮做完，不分期（用户拍板本轮）。
4. **未知模型保守不注入**（用户质询"足够好吗"后修订，对齐 AtomCode/KimiCode/dsh 三家的保守处置；原乐观方案废除，理由见 §4 原则 4）。
5. 切模型清 effort 跟随新模型默认（dsh 语义）。
6. 选择器位置 = Composer 旁（我们无独立模型选择器 UI，dsh 的 conversation.input.model seat 同位）；ProviderPanel 保留为完整编辑器。
7. `/model` 语义从"等价 /provider use"改为"切当前服务商的模型"（多模型后这才是本义）——**CLI 用户可见变化，请用户确认**。
8. dsh 补充调研五候选的取舍：全局默认随选择更新 = 天然满足（写盘即全局默认）；usage reasoning 子标签 = 纳入；provider 失败 warning 条 = 不做（我们 provider 数量少，命令回执错误直接显示）；pending/lastUsed 投影 = 不做（§4 原则 1）；收藏/价格/连接测试 = 不做。
