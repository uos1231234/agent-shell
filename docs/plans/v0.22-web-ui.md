# v0.22 — 自研前端 Web UI（React SPA）+ 宿主装配收尾

> 状态：计划已落盘（2026-09-06 用户拍板后修订），代码待实现
> Depends on：**v0.21 Signal Gate 基础设施**（`src/signals/` + `src/webshell/`）——前端只连 v0.21 Web 层的 WS/REST 契约
> Blocks：桌面壳（Electron/浏览器加载本 SPA）、移动端、产物工作台
> **本计划 = v0.21 装配收尾（宿主入口）+ 后端三处最小扩展 + 前端完整 UI（纯自研 React）**

## 0. 2026-09-06 用户拍板（四项，本轮决策记录）

1. **含正式宿主装配**（`examples/web-host.ts`）——不破坏信号关唯一代理地位：装配代码在后端进程内、位于 gate 的**生产者一侧**（把状态机实例接进 gate handlers），前端只见 WS/REST 契约。`wireSessionToGate` 本就是信号关体系组成部分。
2. **index 免鉴权**：数据面（cmd/snapshot/WS）全部保持强制 Bearer；仅静态空壳放开。前端配套"无 token 引导页"（TokenGate）。
3. **断线恢复 = 后端 history 为事实源 + 前端只存 UI 偏好，交错拼装**：走 cmd 通道加 `session.history` 命令（零新路由，契约集中在 gate）；渲染细节丢失可接受，折叠等偏好存本地。
4. **技术栈**：Radix 原语 + Tailwind v4 + zustand v5；类型共享用 **TS 原生方案**——webapp 经 paths 别名对库源码 `import type`（编译期擦除、零运行时、零同步机制）。

## 1. 约束（Constraints）——本段是 7 段约束

1. **前后端只有信号关系**：webapp 不 import 任何 agent-shell **运行时代码**；只允许 `import type`（编译期擦除，vite 产物零库代码）。类型唯一来源 = `src/signals/index.ts`（及其 type 传递闭包）。
2. **webapp 独立目录同仓**：`agent-shell/webapp/` 独立 package.json / tsconfig / vite 配置，不污染库的 tsconfig/vitest。
3. **后端改动仅限三处**（§4 列出），不新增 guard/metric/config（ADR-015）；其余后端逻辑一律不动。
4. **gate 是唯一中转站**：所有前端→后端指令走 `POST /api/v1/cmd`（GateCommand），所有后端→前端信息走 WS 事件帧。不加第二个 REST 数据路由。
5. **纯自研**：不抄 deepseek client-ui / acp-ui / openyak / kcc 代码；功能对齐 deepseek 核心信息架构（三栏/双视图/工具卡/折叠/deliverables）。
6. **日志面板**（用户拍板）渲染 v0.21 `log` 信号；默认展示 info 及以上，可切换全部/警告+，按 component 过滤。
7. 事实修正（实现时必须遵守，均 [已验证]）：
   - `IMLoopResult.finalState` 只是 `'Running' | 'Tripped'` 字符串——turn.end **不含消息文本**，assistant 文本只能靠 delta 流积累 + session.history 恢复。
   - `StreamChunk` 无 reasoning 类型——`thinking.delta` 是**死信号**；ThinkingBlock 做成"数据源就绪即激活"组件，协议层接入（reasoning_content 解析）留 v0.23。
   - `openSession` 不幂等（每次磁盘恢复全新实例）——装配层必须维护 `openHandles: Map` 缓存。
   - 首屏 401 死锁：fragment token 不上送，index 强制 Authorization 必然 401——本计划修复。
   - `user.prompt` 回执 = runPrompt 全程跑完才返回（HTTP 长挂起）——前端 fire-and-forget，以 WS 信号为渲染真相。

**前端数据流（每条信号的消费方式）**：
```
assistant.delta    → 当前 turnId 的文本追加（turnId 变化 = 新 turn 开始）
tool.started       → turn.toolCalls[callId] = {name, args, result: pending}
tool.result        → turn.toolCalls[callId].result 填充（isError 来自 ToolTurn.isError）
turn.end           → turn.metrics/reason/hits 落档（终止原因徽章）
artifact           → Details/产物 tab 列表；点开 → cmd artifact.get → iframe srcdoc
memory.activity    → Details 记忆 tab（layer/stamp）
session.event      → system.prompt 文本（装配层 emit）+ 其他事件进 timeline
log                → 日志面板环形缓冲（1000 条上限）
approval（请求）    → 全局 pendingRequests 队列 → 审批浮层 → cmd approval.decision
ask_user（请求）    → 提问浮层（options 2-4 / multiSelect / 自由文本）→ cmd ask_user.answer
```

## 5. 模块化引导（Module Guidance）

### 5.1 宿主装配 `examples/web-host.ts`（v0.21 收尾，生产者接线）

公开形态：CLI `tsx examples/web-host.ts --port N --data-dir D --dist webapp/dist [--mock]`

装配步骤（顺序即依赖序）：
1. ToolRegistry：`registerAllTools`（十工具）+ `bootstrapExtensions({ registry, approvalHandler, rendering… })`——approvalHandler 由装配层持有（per-session wire 产物在 createSession 时替换/绑定）。
2. SessionManager（SessionStore 落盘 `--data-dir`）+ `openHandles: Map<SessionId, SessionHandle>`。
3. `createSignalGate({ handlers })`：runPrompt（map 查 handle → buildLoopOptions → runIMLoop）、session.create/open/close/delete/**history**（全部经 openHandles map；open 先查 map、miss 才 openSession；close/delete 后从 map 移除）、cancel/revokeAll/setFullPermission（SecurityRouter 门面）、getArtifact（渲染 base.getHtml → `{id,kind,title,html}`）。
4. 全局：`wireLogSinkToGate`（logger.setSink 一次）；每会话：渲染三件套（bus/base/store）+ `wireSessionToGate` → onStreamChunk/gateHooks/requestHandler/approvalHandler 注入 SessionLoopBase/bootstrapExtensions。
5. session.create/open 成功后 `gate.emit({kind:'session.event', event:'system.prompt', data:{text: systemPrompt}})`——信源透明的系统提示词部分（context 注入内容 loop 内部读取，v0.23 加 prompt.assembled 信号再做全量）。
6. `createWebShellServer({ gate, distDir })` + 打印 `#token=` URL。
7. LLM：`--mock` 或无 ARK_KEY 时用 scripted streamChat（回放：文本 delta → write 工具调用（触发审批闭环）→ 结束），否则 ARK（ARK_KEY/ARK_URL/ARK_MODEL，沿用 v0.15 先例）。
8. **不启 preview server**：artifact.get → srcdoc 已闭环，少开一个端口。

## 7. 决策信息（Decisions）

**已决定**（用户拍板 + 技术定案）：
- 四项拍板见 §0。技术栈 Radix+Tailwind v4+zustand v5+react-markdown；类型 = import type 零机制。
- 断线恢复：cursors 在 buffer 内 → replay 增量；越界 → resync → 逐活跃会话 cmd session.history + session.list 刷新；渲染细节丢失可接受，UI 偏好 sessionStorage。
- 审批 UI 无 scope 参数（后端按工具类型自动记账：write=file、bash=session）。
- 前端多标签页/多客户端：事实以 history + WS 为准；用户消息本地 optimistic append（事件流无 user.message 信号——局限写明，v0.23 可在装配层补发 session.event）。
- 日志面板默认 info+；ContextMeter 无上限数据不做百分比。

**未决 / 留给 v0.23**：reasoning chunk 协议接入（激活 ThinkingBlock）；prompt.assembled 信号（context 注入透明全量）；user.message 事件；会话标题自动生成。
