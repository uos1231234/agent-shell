## 0. Goal (one paragraph)

[已读未验 — based on ADR-016 §4.2 and §8 v0.10.2 row, NOT yet cross-checked with v0.10.1 c377e2c code]:

Implement the `StateLine` module — a filesystem-persistent, append-only store for **3 layered views** over the databus: `curatedMemory.jsonl` (L1/L2 11-field blocks written by the compressor agent), `index.jsonl` + `stamps.jsonl` (L3 summaries written by the warehouse agent), and `vectors/chroma/` (RAG vectors written by the warehouse agent via `scripts/embed.py`). On top of this storage, expose a `StateLine` class with `query()` / `subscribe()` / `appendBlock()` / `appendSummary()` methods. **Replace** the v0.10.1 stub `state_query` tool (`src/im/tools/state-query.ts:48` returns the literal string `"no state available in v0.10.1; see ADR-016 §8 v0.10.2"`) with a real implementation that reads jsonl directly for metadata queries, and routes `queryText` to chromadb RAG — **no LLM** in the `state_query` path. Add `stateLine` as an optional field to `IMLoopOptions` in v0.10.2 (required in v0.10.3 per §7.2 decision #4).

**Success criterion**: a `runIMLoop` call that ends with the working agent invoking `state_query({stamps: [...], layer: 'L3'})` returns a real `StateLineEntry[]` (jsonl-direct read, no LLM), and the corresponding jsonl file has a new line written. `state_query({queryText, limit})` returns L3 RAG matches (chromadb cosine, no LLM). LLM-mediated synthesis is the `ask_recall` tool's job, not `state_query`'s.

## 1. Constraints (9 hard rules, do not violate)

[已读未验 — based on reading ADR-016 §2.2, §4.2, §4.5, and the v0.10.1 c377e2c code]:

1. **ADR-016 §2.2 11-field schema is closed** — `CuratedMemory` has 6 required top-level fields + 1 optional + 5 required `working_state` sub-fields. **No `metadata` field** (explicitly retracted). [已读未验 — see ADR-016 §2.2 lines 104-122]
2. **ADR-016 §2.2 single-writer per slot** — `curatedMemory.jsonl` written only by the compressor agent; `index.jsonl` + `stamps.jsonl` + `vectors/chroma/` written only by the warehouse agent; the recall agent writes nothing. The `StateLine` class API must enforce this at the type level (e.g. `appendBlock()` is on a different namespace than `appendSummary()`).
3. **ADR-016 §4.2 default path** — `~/.databus/` is the default. v0.10.1 §4.4 says it is **not yet configurable** — v0.10.2 introduces the `config.databusPath` field per ADR §4.4.
4. **ADR-016 §4.5 RAG bridge protocol is locked** — `scripts/embed.py` is the single Python entry point; stdin/stdout JSON; `{ok, ...}` envelope; exit 0 on errors; default `storePath` = `~/.databus/state/vectors/chroma`; default `collection` = `l3_summaries`. v0.10.2 must use it as-is. [已验证 — c377e2c includes `scripts/embed.py` 183 lines; protocol tested end-to-end in v0.10.0 capability discovery]
5. **RAG model is locked** — `ONNXMiniLM_L6_V2` (all-MiniLM-L6-v2, 384-dim, cosine). Node never loads the model; it goes through `scripts/embed.py`. [已验证 — embed.py uses `chromadb.utils.embedding_functions.onnx_mini_lm_l6_v2.ONNXMiniLM_L6_V2`]
6. **stamp is a stable string** (ADR-016 §2.2, also explicitly called out in `src/im/tools/state-query.ts:4` and `src/im/tools/state-query.ts:29`) — **not a timestamp number**. `StateLine` API must use `string` type for stamps.
7. **vector metadata is `{ stamp }` only** (ADR-016 §4.2 invariant, also explicit in `src/im/prompts/warehouse-agent.md:38-40`) — never duplicate `summary_text` or any other field in the chromadb metadata. Duplication creates drift.
8. **appended-only** (ADR-016 §4.2) — `curatedMemory.jsonl` / `index.jsonl` / `stamps.jsonl` are append-only. Never edit a previous line. If a block is wrong, append a new line that supersedes.
9. **No new `IMLoopResult` fields** (v0.10.1c §7 explicit) — the working agent's return type stays exactly as c377e2c shipped it. v0.10.2's changes are inside `IMLoopOptions` (1 new field) and inside the `state_query` tool's `execute` body.

## 3. Architecture (the 3-layer information model)

[已读未验 — based on ADR-016 §2.2 and warehouse-agent.md, cross-checked with v0.10.1 c377e2c stub]:

```
┌──────────────────────────────────────────────────────────────────┐
│                       Working agent                                │
│                       (LLM session)                                │
│  Has 7 v0.10.1 tools including state_query                         │
│  state_query.execute calls warehouse agent.run() with JSON args   │
└──────────────────────────────────────────────────────────────────┘
                              │
                              │ warehouse agent (full runIMLoop, v0.10.1)
                              │ reads databus + curatedMemory + index
                              │ writes index.jsonl + stamps.jsonl + vectors
                              ▼
┌──────────────────────────────────────────────────────────────────┐
│   StateLine class (NEW in v0.10.2, src/im/state-line/index.ts)   │
│                                                                   │
│   read API:                          write API:                    │
│   ┌─────────────────────────┐         ┌──────────────────────────┐│
│   │ query({stamps,range,    │         │ appendBlock (L1/L2)      ││
│   │       layer,limit})      │         │  → curatedMemory.jsonl    ││
│   │  → StateLineEntry[]     │         │  → only callable by       ││
│   │                         │         │    compressor agent       ││
│   │ subscribe(...)          │         │                          ││
│   │  → Unsubscribe          │         │ appendSummary (L3)       ││
│   │                         │         │  → index.jsonl +          ││
│   └─────────────────────────┘         │  → stamps.jsonl +         ││
│                                       │  → scripts/embed.py       ││
│                                       │  → only callable by       ││
│                                       │    warehouse agent        ││
│                                       └──────────────────────────┘│
└──────────────────────────────────────────────────────────────────┘
                              │
                              │ physical storage
                              ▼
   ~/.databus/state/
   ├── stamps.jsonl          # {stamp, path, layer, written_at}  (NEW)
   ├── curatedMemory.jsonl   # 11-field CuratedMemory              (NEW)
   ├── index.jsonl           # {stamp, l1_stamp, summary_text,     (NEW)
   │                         #  layer: 'L3', at}
   └── vectors/chroma/       # chromadb PersistentClient,          (NEW)
       │                      collection 'l3_summaries'
       │                      (created by scripts/embed.py)
       └── chroma.sqlite3 + hnsw segments
```

**Key design points** (from ADR-016 §2.2 invariants):
- `curatedMemory.jsonl` (L1/L2) and `index.jsonl` (L3) are **separated** — different writers, different schemas, different lifecycles
- `stamps.jsonl` is the **join key** — every stamp that appears in either `curatedMemory` or `index` also appears in `stamps.jsonl` with its physical path
- `vectors/chroma/` is the **RAG side** — every L3 stamp also has a vector with the same stamp as metadata

**Single-writer enforcement** (the design point that makes this safe under concurrency):
- `appendBlock()` can only be called by the compressor agent's inner `runIMLoop` (which holds the compressor `SystemAgent` instance); the API surface is on a sub-object that the warehouse agent does not have access to
- `appendSummary()` can only be called by the warehouse agent's inner `runIMLoop`; the compressor agent does not have access to this API
- This is **type-level enforcement**, not runtime gating — the warehouse agent's `toolRefs` simply do not include the L1/L2 write API

## 4. Design principles (6, plan-specific)

1. **Append-only jsonl, not SQLite.** Per ADR-016 §4.2: `grep / awk` debuggable, file-level lock-free (3 system agents can write concurrently without DB transactions). The trade-off: no indexed query — we do the indexing in the warehouse agent's `update_index` tool, which keeps the storage layer dumb.
2. **chromadb `PersistentClient` over hand-rolled `vectors.bin`.** Per ADR-016 §4.2 (and the v0.10.0 RAG discovery): HNSW + cosine similarity + metadata filtering (by `stamp`) for free. Premature optimisation (binary mmap) was rejected.
3. **RAG via Python bridge, not native Node binding.** Per ADR-016 §4.5: onnxruntime-node and Node chromadb clients are not mature. `child_process.spawn` is the lowest-risk option. Trade-off: 1.3s cold start per call — acceptable because warehouse agent batches (one `embed.py` call per L3 block).
4. **Type-level single-writer enforcement, not runtime gating.** The `StateLine` class exposes `appendBlock` and `appendSummary` on **different sub-objects** (`compressorInterface` and `warehouseInterface`). The compressor `SystemAgent` only gets `compressorInterface`; the warehouse `SystemAgent` only gets `warehouseInterface`. This makes "compressor wrote to index.jsonl" a compile error.
5. **stamp is the only join key, no other metadata drift.** Per ADR-016 §4.2 invariant + `warehouse-agent.md:114-115` ("the #1 bug source in v0.10"). The `vectors/chroma/` metadata is `{ stamp }` and only `{ stamp }` — duplicating `summary_text` there would create two truths.
6. **Persistence boundary: state-line survives sessions, databus and mailbox do not.** Per ADR-016 §2.2 lifecycle. v0.10.2's `StateLine` class is the **only** object that holds filesystem handles; the working agent's `IMLoopOptions` accepts a `StateLine` instance and the runtime never closes it (it's a per-session concern, but writes survive the session).

## 5. Module guidance (3 new files, 1 modified file, 1 new test)

### 5.1 NEW: `src/im/state-line/index.ts` (public API surface)

```
Public types (exported):
  StateLine                      // the class itself
  StateLineEntry                 // one block returned by query() / subscribe
  CompressorInterface            // sub-object with appendBlock() only
  WarehouseInterface             // sub-object with appendSummary() only
  StateLineConfig                // { databusPath: string } (v0.10.2 introduces this field)

Public factory:
  createStateLine(config?: StateLineConfig): {
    // The two sub-interfaces (single-writer enforcement):
    compressor: CompressorInterface
    warehouse: WarehouseInterface
    // The shared read API:
    query(filter: { stamps?: string[]; range?: [number, number]; layer?: 'L1' | 'L2' | 'L3' | 'ARCHIVE'; limit?: number }): readonly StateLineEntry[]
    subscribe(filter: ...): Unsubscribe
    // Lifecycle:
    close(): void
  }
```

Where it lives: `src/im/state-line/index.ts` (re-exports from `state-line.ts` + `types.ts` + `jsonl-writer.ts` + `chroma-bridge.ts`).
Depends on: `Databus` (read-only for warehouse's `update_index` tool), Node `fs` / `path` / `child_process`.

### 5.2 NEW: `src/im/state-line/types.ts` (the schemas)

```
Export 3 types, all frozen as TypeScript types (no runtime validation here — validation is the compressor agent's job):

  CuratedMemory                   // 11-field schema, ADR-016 §2.2 verbatim (NO metadata field)
  L3Summary                       // { stamp, l1_stamp, summary_text, layer: 'L3', at }
  StampRecord                     // { stamp, path, layer: 'L1' | 'L2' | 'L3', written_at }
  StateLineEntry                  // union: CuratedMemory | L3Summary (returned by query)

  Stamp is `string` (NOT number) — see state_query.ts:4 comment in v0.10.1 c377e2c.
```

### 5.3 NEW: `src/im/state-line/jsonl-writer.ts` (the dumb storage)

```
Single function:
  appendJsonl<T>(filePath: string, record: T): Promise<void>

Behavior:
  - mkdir -p the parent dir if missing
  - fs.appendFile with `JSON.stringify(record) + '\n'`
  - No lock — relies on POSIX append atomicity for single-writer per file
  - Returns when the OS reports the write is durable (default fs.appendFile behavior)

Why single function:
  - 3 files use the same write pattern (curatedMemory.jsonl, index.jsonl, stamps.jsonl)
  - User said "允许有一定冗余" but this is the "dumb" layer — no business logic
  - 10 lines, no abstraction
```

### 5.4 NEW: `src/im/state-line/chroma-bridge.ts` (the Node → Python bridge)

```
Two functions, both thin wrappers over `child_process.spawn`:

  embedL3(items: { stamp: string; text: string }[]): Promise<{ ok: true; count: number } | { ok: false; error: string }>
  queryL3(queryText: string, limit: number): Promise<{ ok: true; results: Array<{ stamp: string; distance: number; document: string }> } | { ok: false; error: string }>

Implementation contract (locked by ADR-016 §4.5):
  - Spawn `D:\trae\runtime\python\python.exe` with args ['agent-shell/scripts/embed.py']
  - Write JSON request to stdin, close stdin
  - Read ONE JSON object from stdout (parse or throw on multi-line)
  - Errors are {ok:false,error:string}, exit 0
  - DEFAULT_PYTHON_PATH is hard-coded in v0.10.2; TODO for `config.pythonPath` in v0.10.3+

Why a separate file (not inline in state-line/index.ts):
  - The Python bridge is the ONLY place that touches Python
  - It can be unit-tested in isolation with mock child_process
  - The warehouse agent's tools will import it directly
```

- **No native Node binding to chromadb/onnxruntime** — ADR-016 §4.5 explicitly rejected (maturity concerns).

### 7.2 Decisions resolved (user-approved 2026-08-28)

1. **`state_query` semantics** — **metadata-only, never LLM-synthesized**:
   - `state_query({stamps?, range?, layer?})` → reads jsonl directly via `stateLine.query()` (cheap, ~10ms)
   - `state_query({queryText, limit?})` → routes to chromadb RAG via `stateLine.queryL3()` (~50-200ms, NO LLM)
   - LLM-mediated free-text synthesis is **not** `state_query`'s job — that is `ask_recall`'s job (v0.10.1 c377e2c already ships it)
   - **Why this is the right separation**: `state_query` is a storage-layer lookup; `ask_recall` is an LLM-synthesis tool. Two tools, two layers, no semantic overlap.
2. **`ToolContext` on `ToolRegistry.execute`** — **optional with default `{}`** (USER-APPROVED):
   - 1-line change in `src/shell/registry.ts:92`
   - v0.9's 8 tools keep their `(args)` signature unchanged; only `state_query` (1 of 7 new tools) actually reads `ctx`
   - `ctx.stateLine` is the only field `state_query` uses; `ctx.mailbox` / `ctx.workingAgentId` / `ctx.systemAgents` are **not** read by any v0.10.2 tool (the system-agent closures already capture their own deps)
3. **Python timeout for `embed.py` spawn** — **15 seconds default**, configurable via `StateLineConfig.pythonTimeoutMs` (USER-APPROVED, increased from my proposed 10s):
   - Actual usage: ~1.3s cold start + <0.5s processing = ~2s typical
   - 15s gives ~7x safety margin
   - Rationale: covers slow disk / first-chromadb-compile / network retry inside chromadb; anything past 15s is a hard fault and should surface immediately
4. **`IMLoopOptions.stateLine` is OPTIONAL in v0.10.2, REQUIRED in v0.10.3** (USER-APPROVED, follows my detailed-explanation recommendation B):
   - v0.10.2: `stateLine?: StateLine` — `createMinimalIM` provides a `NoopStateLine` default so v0.10.1 callers and the 36 existing test files do not need to change
   - JSDoc on the field MUST say: `/** Will be required in v0.10.3. */`
   - v0.10.3 upgrade: remove the `?`, remove the noop default, force all callers to pass a real `StateLine` instance — the upgrade is "make it required", a 1-line change per caller (~10+ files)
   - Total fields: **15 required + 1 optional in v0.10.2** (vs. v0.10.1's 15 required — no change in field count, only the new one is optional)
5. **`stamps.jsonl` idempotency** — **duplicate silently, reader de-duplicates** (USER-APPROVED):
   - `appendStamp(stamp, path, layer)` always appends; never checks for duplicates
   - `stateLine.query({stamps: ['S-1']})` returns the **first** matching record (or all matches if explicitly requested via a future `allMatches` flag — not in v0.10.2 scope)
   - The "duplicate" case is rare in practice (only happens after warehouse agent crash + restart); when it does happen, the **read** side is the one place that knows how to interpret it
   - This is append-only's natural semantics: the file is the truth, even if it contains redundancy
