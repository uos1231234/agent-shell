# v0.20 — Rendering 基座：信号发射器 + Hook 触发 + 前端交互接口（wiki 为第一个消费者）

> **Depends on**: HEAD（v0.19 prompt 工程 + v0.17 LoopHooks + v0.18 渐进披露 + v0.13.1 wiki agent；未 commit 工作树含 v0.19 改动）。
> **Blocks**: wiki 前端（宿主应用 webview / preview server 消费者）、未来任何"工具产物富渲染"场景。
> **Plan status**: implementation plan. 等用户拍板后再动代码。
> **对标依据**: AtomCode daemon `ArtifactDetector`（本地对标仓库 **不采用**其流式字符级状态机（用户拍板：状态机过重）；采用"hook → 信号发射器 → 基座"三段解耦。KimiCode `vis` server（apps/vis/server/src/start.ts）作为 preview server 参照。

## 0. 一句话定位

给 harness 增加一个**静默渲染基座**（`src/rendering/`）：LLM 调用 `wiki__render_md` 等工具产出 md 后，渲染 HTML、落 artifact store、向宿主前端广播——**全程不加 LLM 工具、loop 状态机零改动**。链路：

```
loop.ts（[HOOK 5] afterToolExecution 挂点，ToolTurn 新增 toolName 字段）
   │
   ▼ renderingLoopHook（薄转发：拿到 toolName + result，原样塞给发射器）
RenderingSignalBus（信号发射器 = event 池子 + 注册制规则表；匹配则发射 ArtifactSignal）
   │
   ▼ 基座作为唯一内置订阅者
RenderingBase（renderMarkdown / ArtifactStore / onArtifact 事件流 / startPreviewServer）
   │
   ▼ 前端交互接口（进程内事件 或 http://localhost:<port>，宿主/用户拉起）
宿主应用 webview / 浏览器
```

**用户已拍板**（2026-09-04）：
- 展示是静默服务，**不做系统工具**（推翻本计划初稿的 render_md/open_preview 工具方案）。
- hook 增加"分支"的手法 = **信号发射器**：event 池子做触发规则表，匹配即发射基座启动信号并完整转发信息。
- wiki-mcp `render_md` **带内容返回**（方案 B）——避免链路通了之后更难改。
- **ToolTurn 加可选 `toolName` 字段**（databus.ts）——追踪发现 afterToolExecution hook 拿到的 ToolTurn 缺工具名，规则表无法匹配；4 个构造点（loop.ts:189/212/228/251）都有 `tc.function.name` 可用。
- **extract 优先顺序**：try JSON.parse → 失败或 markdown 被截断 → fallback 读 `file` 路径（大快照常态走 fallback，因为 registry 10K 截断会把 JSON 从中间切断）。
- **Q1**：知识卡片是"用户看书一样"的全页渲染（书页间有逻辑关系链接），不是嵌入式卡片。起步支持 10 项 markdown 子集（见 §7）。
- **Q2**：基座/bus **不进 createMinimalIM 默认装配**，由宿主 caller 手动接（参考 wiki security hook 模式）。
- **Q3**：preview server **本期做**（~100 行，KimiCode vis 已验证该形态）。

## 1. 约束（Constraints，共 8 条）

1. **C1（架构分层）**：`src/rendering/` 与 `src/security/` 平级，依赖方向单一：`loop → hooks → rendering-hook → signal-bus → base`。**基座不 import loop / registry / protocol**；`rendering-loop-hook` 是唯一 import LoopHooks 类型的文件。
2. **C2（loop 最小改动）**：**仅**给 `ToolTurn` 加可选 `toolName` 字段（databus.ts）+ 4 个构造点填 `tc.function.name`（loop.ts:189/212/228/251）。**不改** `runIMLoop` 主体、不改 `IMLoopResult`、不改 `StreamChunk`。渲染触发全部经由既有挂点 `[HOOK 5] afterToolExecution`（loop.ts:805-812）。
3. **C3（ADR-015）**：不新增 guard / metric / config 字段。发射器与基座的失败一律 fail-safe（吞错 + `logger.warn`），不打断回合。
4. **C4（ADR-020 必保事件）**：新增子系统必须至少 emit 结构化日志。本模块必保：`rendering: signal emitted`（info，含 rule 名 + signal kind）、`rendering: render ok/failed`（info/error）、`rendering: preview server start/close`（info）。挂在 `src/shared/logger.ts` 既有 5 级 + child bindings 上，不新建日志设施。
5. **C5（ADR-019 wiki 边界）**：wiki 规则只识别 `wiki__render_md` 一个工具名；不放宽 `wiki__` 安全守卫（`ctx.isWikiAgent` 检查原样保留）。规则注册点在 wiki agent 装配路径（与 wiki security hook 同文件），不在基座内置。
6. **C6（零新依赖）**：md→HTML 是零依赖手写解析器（参照文学版 `md2html-snapshot.py` 的逐行状态机，但**输出 HTML 而非整页模板**——模板归前端）；preview server 用 `node:http`（KimiCode vis 用 Hono，我们不引依赖，只借鉴其"自动选端口 + auth token + 静默起"的行为）。
7. **C7（wiki-mcp 零依赖不变）**：`wiki_server.js` 仍是纯 Node 内置模块；`render_md` 返回值加 `markdown` 字段是**在既有 textResponse JSON 里加一个 key**，不引入序列化依赖。
8. **C8（v0.19 HookSystem 状态）**：`HookSystem`（hooks/hook-system.ts）已有 PostToolUse wiring（loop.ts:224-236），但 `HookSystem` 实例的**装配点目前无 caller 构造**（[已读未验] 全 src 无 `new HookSystem()` 消费者，仅 minimal.ts 转发 opts.hookSystem）。本计划默认走 **[HOOK 5] LoopHooks 路径**（v0.17 已完整落地、测试覆盖）；若用户要求走 HookSystem，需先补装配，见 §7 D2。

┌─────────────────────────────────────────────────────────────────────┐

## 4. 设计原则（Principles，6 条）

1. **判断与触发解耦是本仓库固定写法**：signal-bus 复刻 `memory-layers.ts` SignalBus 的"分类器只发信号、业务 on() 订阅"模式（v0.10 拍板）。规则表就是发射器的池子数据，不写成 hook 里的 if-else。
2. **工具结果边界是识别点，不是文本流**：回合内工具结果是完整、有限、可 JSON 反序列化的，识别退化成查表；换来 loop 零侵入与规则无状态。
3. **基座是被动执行者**：基座收到信号才动，没有定时器、没有轮询、不主动读 databus。它的公开面只对前端（onArtifact / list / get / preview server）。
4. **内容大≠信号大**：信号内嵌 content 只允许 ≤ 64KB；超限规则必须返回 artifact-ref 形态（extract 内先 store.put 再构造信号），信号永远是常量级大小。防止规则把快照级内容（60KB+）拖进事件流。
5. **静默是契约不是实现细节**：LLM 侧 tool result 形状不变（`{success, file, sizeBytes, ...}`，B 方案加 `markdown` 字段但截断预览 ≤ 2KB，完整内容走 artifact-ref 信号），LLM 不感知渲染发生，也不需要为渲染付任何 token。
6. **前端接口先于前端实现**：本计划只交付基座的接口面（类型 + 进程内事件 + preview server 的 HTTP 契约），不做任何具体前端页面——那是消费侧（宿主应用 /  独立页面）的后续计划。

## 5. 模块化引导（Module Guidance）

### 5.1 `src/rendering/render-md.ts`（纯函数解析器）

```ts
/** md → html。零依赖。mermaid 围栏透传为 <pre class="mermaid-raw">，归前端渲染。 */
export function renderMarkdown(md: string): string
```
- 支持子集（对照文学版解析器 + marked 常用面）：ATX 标题、 fenced code（保留语言标签）、表格（`|` 管道）、引用块、有序/无序列表、行内（粗体/斜体/行内代码/链接）、分隔线、段落。mermaid / html 围栏**原样转义透传**，不解析。
- 定义于 `src/rendering/render-md.ts`；无 import（纯函数）；基座消费；纯函数单测全覆盖（含 CJK、表格转义、未闭合围栏）。
- 边界明确：**不做**语法高亮、不做 mermaid 服务端渲染、不做目录生成——全是前端职责。

### 5.2 `src/rendering/signal-bus.ts`（发射器）

```ts
export type ArtifactSignal =
  | { kind: 'markdown'; title: string; source: string; content: string }          // ≤ 64KB
  | { kind: 'artifact-ref'; title: string; source: string; artifactId: string;
      sizeBytes: number; mime: 'text/html' | 'text/markdown' }

export type RenderRule = {
  name: string                                    // 日志/调试标识
  match(toolName: string): boolean
  extract(parsed: unknown): ArtifactSignal | undefined
}

export type RenderingSignalBus = {
  registerRule(rule: RenderRule): () => void      // 返回注销函数
  emit(toolName: string, turn: ToolTurn): Promise<void>   // fire-and-forget：订阅者异常吞 + warn
  onSignal(h: (s: ArtifactSignal) => void | Promise<void>): () => void
}
export function createRenderingSignalBus(opts?: { logger?: Logger }): RenderingSignalBus
```
- 定义于 `src/rendering/signal-bus.ts`；import `ToolTurn` 类型（databus.ts）+ Logger——**这是全模块唯一允许 import `im/` 的地方（仅类型）**，因为 ToolTurn 是挂点契约的形状；嫌越界可把信号入参改成 `ReadonlyArray<{toolName: string; result: unknown}>`（§7 D3）。
- 规则按注册顺序匹配，一条信号只发一次（首个 extract 非 undefined 的规则胜出）；emit 串行 await 广播（订阅者顺序 = 注册顺序）。

### 5.3 `src/rendering/base.ts`（基座 + 前端交互接口）

```ts
export type ArtifactHandle = {
  id: string                       // sha256 前 16 hex（store 去重）
  kind: 'markdown' | 'html'
  title: string
  source: string                   // 'wiki__render_md snapshot' 这类来源描述
  at: number
}
export type RenderingBase = {
  renderMarkdown(md: string, meta: { title: string; source: string }): ArtifactHandle
  handles(): readonly ArtifactHandle[]
  onArtifact(cb: (h: ArtifactHandle) => void): () => void     // 前端交互接口（进程内）
  getHtml(id: string): string | undefined                      // 前端拉取（HTML 正文）
  startPreviewServer(opts?: { port?: number; host?: string }): Promise<{ url: string; close(): Promise<void> }>
}
export function createRenderingBase(bus: RenderingSignalBus, opts?: {
  logger?: Logger
  store?: ArtifactStore          // 默认自建；测试可注入
}): RenderingBase
```
- `createRenderingBase` 内部 `bus.onSignal(...)` 完成订阅——**装配方只把两者接在一起，不写任何转发代码**。
- preview server：`node:http`；仅 `GET /artifact/:id`、`GET /list`、`GET /healthz`；端口默认 0（自动选）；**不加 auth token**（v1 只绑 127.0.0.1，见 §7 D6）。
- 定义于 `src/rendering/base.ts`；依赖 render-md.ts、artifact-store.ts、signal-bus.ts 类型；被 `src/index.ts` 导出。

### 5.4 `src/rendering/hooks/rendering-loop-hook.ts`（薄转发 hook）

```ts
export const createRenderingLoopHook = (bus: RenderingSignalBus): AfterToolExecutionHook
```
- 实现 = 对 `toolResults` 逐条 `bus.emit(toolName, turn)` 后 `return undefined`。**没有第二行逻辑**。
- 定义于 hooks 子目录；import LoopHooks 类型 + signal-bus 类型；被装配方拼进 `IMLoopOptions.hooks`。

### 5.5 `src/rendering/rules/wiki.ts`（wiki 规则）

```ts
export const WIKI_RENDER_RULE: RenderRule
// match:    toolName === 'wiki__render_md'
// extract:  try JSON.parse(content) →
//           ① parsed.success && typeof parsed.markdown === 'string' 且未被截断
//              → kind:'markdown'（≤64KB）或 kind:'artifact-ref'（>64KB，先 store.put）
//           ② JSON.parse 失败 或 markdown 字段被 '...[truncated]' 截断
//              → 读 parsed.file 路径取完整 md → kind:'artifact-ref'（大快照常态）
//           ③ 无 success/file → undefined（不发射）
```
- **B 方案落点 + 追踪修正**：extract 优先读信号里的 `markdown` 字段；**但** registry 的 `truncateResult`（10K 上限）会把 JSON 从中间切断 → JSON.parse 抛错 → 此时 fallback 读 `file` 路径。**大快照（>10K JSON）常态走 fallback**，不是"偶尔"。测试必含：截断命中 fallback、reminder 包裹穿透、未闭合围栏不崩。
- 定义于 rules 子目录；由 `wiki-agent.ts` 的 `createWikiAgent` 在注册 security hook 的同一位置调用 `bus.registerRule(WIKI_RENDER_RULE)`——**基座/bus 实例从哪来**：`CreateWikiAgentDeps` 增加可选 `rendering?: { bus; base }`，未传则**跳过注册**（wiki 照常工作，只是不渲染——向后兼容）。

### 5.6 wiki-mcp `wiki_server.js` 改动（B 方案，1 个 case）

```js
// render_md 两个分支的 textResponse 增加字段：
{ success: true, file, sizeBytes, mode, markdown: md }   // snapshot 分支
{ success: true, file, sizeBytes, mode, card_id, markdown: md }  // card 分支
```
- **完整 md 放进 tool result**。LLM 侧成本控制：registry 的 `truncateResult`（10K 上限）会把它截成预览——这正好符合"LLM 只需要知道渲染成功 + 看个开头"的静默契约（§4.5）；**信号侧 extract 按 §5.5 的优先级处理**：JSON 完整 → 直接用 markdown 字段；JSON 被截断 → fallback 读 `file` 路径（大快照常态路径）。
- 同时更新 `getTools()` 里 render_md 的 description（注明"返回含 markdown 内容，宿主负责渲染，LLM 无需转述全文"）。

## 7. 决策信息（Decisions）

### 已决定（带理由）

| # | 决策 | 理由 |
|---|---|---|
| D1 | 静默渲染，**不做 LLM 工具** | 用户拍板；对标三家 harness 均为"内容照常产生 + 宿主旁路渲染"，LLM 零感知 |
| D2 | 挂点选 `[HOOK 5] afterToolExecution`（LoopHooks），**不选** HookSystem PostToolUse | LoopHooks v0.17 完整落地且有 `transformedResults` 显式契约 + fail-safe `callHook`；HookSystem 虽已在 loop 内接线（PostToolUse 拿到 raw result），但**实例无装配 caller**，用它需先补装配——本计划不为渲染挪基建。代价：拿到的是 stringify 后 content，bus 需 JSON.parse 容错 |
| D3 | bus.emit 入参 = `(toolName, ToolTurn)`，bus 内部 parse | 保持 hook 一行转发；ToolTurn 仅作类型 import（若实现时发现产生 im→rendering 反向运行期依赖，退化为 `ReadonlyArray<{toolName; result}>`，在实现 PR 里定，不影响契约面） |
| D3a | **ToolTurn 加可选 `toolName: string` 字段**（databus.ts:7-15）+ 4 个构造点（loop.ts:189/212/228/251）填 `tc.function.name` | 追踪发现：afterToolExecution hook 拿到的 ToolTurn **没有工具名**（已验证 databus.ts:7-15 6 个字段均非工具名），规则表无法匹配。`tc.function.name` 在 4 个构造点都可用。可选字段 → 零破坏（现有测试不要求 ToolTurn 无多余字段） |
| D4 | wiki 规则 extract 优先级：**①** try JSON.parse → markdown 字段完整 → 直接构造信号（≤64KB 走 kind:'markdown'，>64KB 走 artifact-ref）；**②** JSON.parse 失败 或 markdown 被 `...[truncated]` 截断 → fallback 读 `file` 路径（**大快照常态路径**，因 registry 10K 截断会把 JSON 从中间切断）；**③** 无 success/file → 不发射 | 追踪修正：原计划称"主路径纯函数化、fallback 偶尔用"——实际 truncateResult 对 >10K 的 JSON 必截断，大快照（文献版 61KB）常态走 ②。测试必含：截断命中 fallback、reminder 包裹穿透、未闭合围栏不崩、content 恰好以 `...[truncated]` 结尾的罕见串（幂等读盘，无害） |
| D5 | **不做**流式文本 artifact（助手输出里的裸 ```mermaid 围栏） | 用户拍板"状态机不要重"；裸围栏归宿主 md 渲染（宿主应用 已有 marked 链路）。本计划范围 = 工具产物渲染 |
| D6 | preview server v1 绑 `127.0.0.1`、无 token、无目录服务 | 只服务内存 artifact 池（非磁盘路径），攻击面=本机进程内内容；token/auth 对齐 KimiCode vis 的完整版留 v0.21（若暴露面扩大再说） |
| D7 | `CreateWikiAgentDeps.rendering` 可选，未传 = 无渲染但不报错 | 向后兼容：现有 28 个 wiki 测试文件与真实 LLM 用例不被打断；渲染是增强不是依赖 |
| D8 | ADR：本计划落地时写 **ADR-024 rendering base**（静默渲染、信号发射器模式、与 ADR-019 的关系） | ADR-019 §Decision 6 的"前端契约"由本计划接棒具体化 |
