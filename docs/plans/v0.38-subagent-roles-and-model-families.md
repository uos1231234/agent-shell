## 0. 现状核实结论（三个缺口，全部属实）

### 缺口 1 — 没有任何预置子代理

- `~/.databus/agents/` 目录**存在但为空**；全仓 `.json` agent 定义零命中。
- `SubAgentConfig.systemPrompt` 是**必填字段**（`src/im/sub-agent/config.ts:134`）→ 没有角色定义就注册不了。
- 结论：用户拿到的是一个"得自己写子代理"的机制，**没有开箱能用的探索/改码子代理**。

### 缺口 2 — 提示词里没有任何"如何给子代理派活"的内容

- `grep "子代理|subagent" src/im/prompt/*.ts` 只命中注释（讲 run-subagent 前置工作区声明），**模板正文零命中**。
- 结论：主代理不知道任务书该怎么写，也不知道"什么该委托、什么不该"、"委派后要验证什么"。

### 缺口 3 — 子代理没有纪律基底；MINIMAL 模板是孤儿常量

- `run-subagent.ts:180-192` 的组装链只有三段：`WORK_DIR_RULE` + `AGENTS.md 层叠` + `cfg.systemPrompt`。
- **`MINIMAL_PROMPT_TEMPLATE`（含子代理版安全规则、编码原则、代码信息驱动）从未参与** —— 写了 5 个月没用上（接线纪律同类第 7 次）。
- 补充事实：`run-subagent.ts:206` **传了 `contextInjector`** → 子代理**会收到** MEMORY.md / ARCHITECTURE.md 的注入内容（读），却**没有任何指令禁止它去写**。

**安全性说明（避免夸大）**：这不构成安全漏洞——危险命令拦截、敏感路径硬拒、写审批都在 door 机制层，对所有 agent 一视同仁。缺的是**行为纪律**。

## 1. 约束（Constraints）

1. **不碰状态机**：改的是提示词组装与子代理注册，不涉及 guard / 上下文组装顺序 / loop 主循环。
2. **前后端只走信号关**：本轮不涉及前端。
3. **唯一基底 + 双槽位结构不变**（ADR-033 D1）：新增内容只能进"统一段"或"两个槽位"，不得开第三个模板副本。
4. **工具双披露保留**（用户拍板）：`{tooling_section}` 清单 + 工具 schema 两处披露。
5. **安全设计保留**：子代理的安全靠机制层，提示词只补纪律。
6. **子代理不维护文档体系**（用户 2026-09-12 新增要求）：子代理**只读** MEMORY.md / ARCHITECTURE.md，不得写入；发现需要更新就报告给主代理。

## 3. 架构信息（Architecture）

### 3.1 子代理提示词组装的四层（本版本落地）

```
  顺序（用户 2026-09-12 拍板：身份先锚定，再由一般到特殊）
  ┌──────────────────────────────────────────────────────────┐
  │ ① 角色段        你是探索者 / 改码者（预置或用户自定义）      │  ← 身份锚定
  │ ② 工作区声明    WORK_DIR_RULE（权限边界）                  │  ← 在哪儿
  │ ③ 纪律基底      MINIMAL 模板（走模型族路由，只开 persona）  │  ← 通用纪律
  │ ④ AGENTS.md    项目约定层叠                                │  ← 最具体的要求
  └──────────────────────────────────────────────────────────┘
```

> ⚠️ 与现状的差异：①④ 均已存在但**顺序不同**（现状是 工作区 → AGENTS.md → 角色）；
> ③ 是新增；现状的 `cfg.systemPrompt` 从"最后一段"变成"第一段"。

### 3.2 模型族槽位扩展（Phase B）

```
  FULL (主代理)  ：persona 槽 × N 族  +  workflow 槽 × N 族
  MINIMAL (子代理)：persona 槽 × N 族  +  workflow 槽【不注入】
  ────────────────────────────────────────────────────────────
  族       persona              workflow            素材来源
  base     PERSONA_BASE         WORKFLOW_BASE       minimax.txt
  deepseek PERSONA_DEEPSEEK     WORKFLOW_DEEPSEEK   deepseek.txt   [已有]
  glm      PERSONA_GLM          (复用 BASE)         glm.txt        [已有]
  kimi     PERSONA_KIMI         WORKFLOW_KIMI       kimi.txt       [新增]
  qwen     PERSONA_QWEN         WORKFLOW_QWEN       Qoder prompt.txt [新增]
  gpt      PERSONA_GPT          WORKFLOW_GPT        gpt.txt        [新增]
  claude   PERSONA_CLAUDE       WORKFLOW_CLAUDE     anthropic.txt  [新增]
```

## 4. 设计原则（Principles）

1. **身份在最先**：角色段置顶，后续所有指令都在"我是谁"的框架下被解释。
2. **纪律一处管全部**：子代理纪律只在 ③ 一份，角色段只写差异（不重复纪律）。
3. **子代理只读文档体系**：MEMORY.md / ARCHITECTURE.md 是主代理与用户的长期资产，子代理不写。
4. **可检查胜过可计数**：不写无依据的数字阈值（延续 ADR-033 D5）。
5. **素材批判性吸收**：外部素材（MiMo / Qoder）要剥离宿主专属约束，且**拒绝其反模式**。
6. **预置即最小可用**：预置子代理要能用，但不追求覆盖所有场景（用户仍可自定义）。
