## 1. 约束（Constraints）

以下 N 条硬约束，违反即不合格：

1. **注册规范**：新工具必须在 `src/im/tools/index.ts` 的 `createBuiltinTools({cwd})` 里用 `r.registerSystemTool({ name, description, parameters: toSchema(...), category, execute: wrapTool(...) })` 注册。**不得**在别处注册。
2. **schema 规范**：参数用 `toSchema(props, required)`；每个工具 schema 必须含 `reason: reasonField`（**不在** required 里）；`execute` 内部用 `dropReason(i)` 剥离 reason。
3. **报错规范**：工具内部 throw 干净英文句子 → `wrapTool` re-throw → `loop.ts` catch 格式化为 `Tool "X" failed: <msg>`（ADR-013）。**工具内不自行格式化**。
4. **安全规范（v0.16）**：所有工具调用经 `registry.execute()` → `securityRouter.check()`。新工具**不得绕过**；读工具（`ast_grep`）无审批负担，写工具（`search_replace`）走 `write-approval` door（bootstrapExtensions 已注册）。
5. **路径规范**：读操作用 `resolvePathForRead(cwd, input)`（检查存在性 + not-found hint）；写操作用 `resolvePath(cwd, input)`（不检查存在性）。见 `src/im/tools/path.ts`。
6. **category 规范**：`ToolCategory = 'read' | 'write' | 'command'`。读工具 → `'read'`，写工具 → `'write'`。并发上限自动继承（read=5 / write=3）。
7. **不引入新运行时依赖**：项目哲学是零外部运行时依赖（仅 `@modelcontextprotocol/sdk`）。`search_replace` 复用现有 `glob.ts` + `path.ts` 的 gitignore；`ast_grep` 走 shell out（仿 rg-resolver 模式，无新依赖）。
8. **不改动**：`src/shell/registry.ts`、`src/security/`、`src/im/loop.ts`、`src/im/minimal.ts`、`src/im/system-agent.ts`、`src/im/tools/run-subagent.ts`、`src/shared/tool-context.ts`、`src/protocol/`、`src/mcp/`、`src/extensions.ts`——这些是已 commit 的稳定面，本次任务不触碰。
9. **高内聚低耦合**：每个工具自包含（纯函数 + 独立文件），`index.ts` 只做注册，不承载逻辑。工具间不互相依赖（`fetch_output` 不 import `search_replace`）。

## 3. 架构信息（Architecture）

### 3.1 三个新工具的信息流

```
┌────────────────────────────────────────────────────────────────────┐
│ createBuiltinTools({cwd})  (src/im/tools/index.ts)                 │
│                                                                    │
│  ├─ search_replace  (category: 'write')                            │
│  │    args: { pattern, replacement, glob?, path?, regex?, reason }│
│  │    ↓ resolvePath(cwd, path) → glob 匹配 → 逐文件读改写          │
│  │    ↓ 返回 { filesChanged, changes } 摘要                        │
│  │    └─ 走 write-approval door（写操作自动审批）                   │
│  │                                                                 │
│  ├─ ast_grep       (category: 'read')                              │
│  │    args: { pattern, path?, lang?, limit?, reason }              │
│  │    ↓ resolvePathForRead(cwd, path) → 找 ast-grep 二进制 →       │
│  │      spawn 子进程 → 解析输出                                    │
│  │    └─ 只读，无审批负担                                          │
│  │                                                                 │
│  └─ fetch_output   (category: 'read')                              │
│       args: { artifactId, offset?, limit?, reason }                │
│       ↓ ArtifactStore.get(id, offset, limit) → 切片内容            │
│       └─ 只读；artifactId 由截断标记（v2 改造 bash/read/grep 产出）│
│                                                                     │
│  ┌─────────────────────────────────────────────────────────────┐   │
│  │ registry.execute() → securityRouter.check()（v0.16）         │   │
│  │   ├─ write 工具 → write-approval door（已注册）               │   │
│  │   └─ read 工具 → 无 door 命中，放行                          │   │
│  └─────────────────────────────────────────────────────────────┘   │
└────────────────────────────────────────────────────────────────────┘
```

### 3.2 模块边界

| 模块 | 职责 | 不负责 |
|---|---|---|
| `search-replace.ts` | 跨文件查找替换逻辑（纯函数 + 文件 I/O） | 不解析 glob（用 `glob.ts`）、不写审批（走 door） |
| `ast-grep.ts` | ast-grep 二进制解析 + 子进程执行 | 不做正则搜索（grep 的事）、不做路径校验细节（用 path.ts） |
| `artifact-store.ts` | 内容寻址存储：`put` / `get(id, offset, limit)` | 不触发截断（v2 由 bash/read/grep 调用） |
| `fetch-output.ts` | fetch_output 工具逻辑（薄壳） | 不持有 store 生命周期（store 是 session 级，v2 接 cleanup） |

## 4. 设计原则（Principles）

1. **写操作必须走审批**：`search_replace` 是 write category → v0.16 write-approval door 自动拦截。工具自身**不做**审批逻辑（不 import approval 模块），职责单一。
2. **读操作零审批负担**：`ast_grep` / `fetch_output` 是 read category，无 door 命中，放行。工具不需要知道 door 的存在——安全是 registry 层的横向关注点。
3. **二进制缺失 = 友好报错，非崩溃**��`ast_grep` 找不到二进制时返回干净英文句子（仿 rg-resolver 的 `RgNotFoundError` + 安装指引），让 LLM 知道该怎么做。
4. **artifact store 是纯内存 + 内容寻址**：`fetch_output` 第一阶段不接截断改造（那是 v2），先提供 store + 查询能力。store 键 = 内容 hash，天然幂等。
5. **glob 复用而非重写**：`search_replace` 的文件匹配复用 `glob.ts` 的 `matchGlob` + `path.ts` 的 gitignore，不引入 fast-glob 等新依赖。
6. **边界清晰**：每个文件一个职责，`index.ts` 只注册。子代理任务按文件边界划分，互不重叠。
