## 3. 架构信息（Architecture）

```
goal 轮 N 收尾（toolCalls 为空）→ beforeComplete：
  ① judge 裁决（压缩前，读全量 canonical）
  ② G1 mergeOldestClosedBlock:
       block = findNextTaskBlock(最旧已关闭块)
       ┌─ 触发 A(size):  block ≥ 80K                 ←── 现状不动
       ├─ 触发 B(watermark): context ≥ 200K ──────── ★补丁 (a)：再加"块 ≥ floorTokens"前置门
       │     floor = 5K | 10K（探针实验定，见 §5.1）  ← 17→187 tok 净膨胀的根治点
       └─ 无门槛时：最旧块可能 17 tok → 合并反而膨胀（信封固定开销 ~170 tok > 小块本体）
  ③ G2 distillEnvelopeRun:
       findDistillRun(相邻 mem- 区间)
       ┌─ 现状双门槛：≥4 块 且 ≥40K tok
       └─ ★补丁 (a′)：位置触发——context ≥ 400K 时放宽为 ≥2 块（体量门失效）
            动机：G1 对"结论主导块"比例 ≈ 1.0x 压不动（90K→90K），只有 G2 的
            N→1 有与形状无关的下界；不放宽则 2~3 个中等信封长期滞留直到撞 1M guard。
            N=1（单个巨信封）本期**不折叠**：血缘退化、"折叠"后仍是信封——如实记残留。
  ④ 续跑提醒返回 continueWith → loop 追加 goal- 回合

(b) 上下文组装缝隙（每轮 composePrompt，loop.ts:246-257）：
  parts = [system, injections, ...history(canonical 实况), userTemplate?]
                                          ↑
    现状：判据 = "u1 全文还在 canonical 里吗"（内容扫描）
      u1 被 G1/常规压缩逐出 → 扫描不命中 → 尾部**重新注入全文**
      ⇒ 模型看到：原位 mem- 信封（含 1K 锚点）+ 尾部一份 canonical 里没有的 u1 全文
      ⇒ 三重伤害：①模型视野 ≠ 落盘（幻影）②逐出被无效化（每轮重复上 wire）③goal 模式
         G1 每轮合并使偶发变常态
    ★修复：判据 = "本轮入口是否落过该回合"（run-scoped，等价于 userTemplate 非空）
      入口 append 无条件（C8）⇒ 非空 ⇒ 已进 canonical ⇒ 本轮起注入面恒弃权
      u1 被逐出后**不复活**——压缩的本意就是让它退场，锚点/召回工具才是正道
```

## 4. 设计原则（Principles）

1. **实验先行，阈值由数据定**（用户两次点名）：(a) 的 floor 取 5K 还是 10K、(b) 的可见面后果，都先由探针产出数字再定码，不拍脑袋。
2. **三条触发线语义正交**：size（这块值得压）/ watermark（攒多了要排干）/ position（上下文热了要腾地方）各回答一个问题；放宽只发生在"压力档"，日常档门槛不动——避免把位置触发做成第二条压缩路径与 D7 互斥打架。
3. **判据对齐事实源**：(b) 的正确事实是"入口落没落"，不是"文本此刻在不在"。内容扫描是 v0.27 时代对"入口 append 是否发生"的**运行时重推导**，逐出机制一出现它就推错；直接用构造性事实。
4. **修复不得偷换模型视野**：(b) 会让"u1 被逐出后不再全文上 wire"成为新行为（含常规压缩场景，不仅 goal）——这是可见性**收紧**（对齐 canonical），但必须实验前后对照并向用户明示，见 §7 Q1。
5. **失败语义不动**：G2 位置触发失败仍走 D16 降级（不折叠 + `distill_failed` + 下轮再试）；G1 floor 不产生新失败面（判 none 就是跳过）。

## 5. 模块化引导（Module Guidance）

**阶段 0 · 实验（[已验证]，2026-09-15 两项探针已跑完，数据如下）**

- **5.1 G1 阈值梯度（`mergeGoalBlock` + `estimateBlockTokens` 模拟，CJK 1字=1tok）**：

  | 形状\blockSize | 5K | 10K | 20K | 40K | 80K | 160K |
  |---|---|---|---|---|---|---|
  | **输入主导(80/20)** | env=2220, **+2780压缩** ratio=2.25 | env=3220, **+6780** ratio=3.11 | env=5220, **+14780** ratio=3.83 | env=9220, **+30780** ratio=4.34 | env=17220, **+62780** ratio=4.65 | env=33220, **+126780** ratio=4.82 |
  | **结论主导(20/80)** | env=5220, **+220膨胀** ratio=0.96 | env=9220, **+780** ratio=1.08 | env=17220, **+2780** ratio=1.16 | env=33220, **+6780** ratio=1.20 | env=65220, **+14780** ratio=1.23 | env=129220, **+30780** ratio=1.24 |
  | **纯回答(0/95)** | env=5970, **+970膨胀** ratio=0.84 | env=10720, **+720膨胀** ratio=0.93 | env=20220, **+220膨胀** ratio=0.99 | env=39220, **+780** ratio=1.02 | env=77220, **+2780** ratio=1.04 | env=153220, **+6780** ratio=1.04 |

  信封开销模型：固定字段170tok + conclusion（逐字）+ 头锚1000tok + causal_steps 50tok。
  **结论（用户定 floor）**：floor=10K 过滤掉所有膨胀块（5K纯回答0.84x、5K结论主导0.96x）；floor=5K 允许5K输入主导块压缩（2.25x）但也放过5K纯回答块膨胀（0.84x）。**用户已定 floor=10K**（"大于10K即可压缩，5K 做实验验证"——数据显示5K输入主导有效但纯回答膨胀，10K 是安全边界）。

- **5.2 userTemplate 去重（真实装配 + 假 LLM 服务商，`examples/usertemplate-dedupe-probe.ts`，[已验证]）**：

  探针设计：goal on → u1=`MARKER-u1-DEDUPE-PROBE` → 90K CJK 回复推过80K size门控 → judge not_met×2（round1 block未关闭G1不触发；round2 block关闭G1触发逐出u1）→ round3 met。抓每个请求体的 lastUser 是否含 MARKER。

  **结果**：
  - Request 0（初始轮）：lastUser 含 MARKER ✓（u1 在 canonical 里）
  - Request 2（round1 续跑轮）：lastUser 不含 MARKER ✓（u1 还在 canonical 里，omit 跳过）
  - **Request 4（round2 续跑轮，G1 已逐出 u1）：lastUser 含 MARKER = BUG 确认**
  - canonical 状态：u1 不在 canonical（被逐出），mem- 信封存在

  **结论**：`omitUserTemplatePart` 内容扫描判据在 u1 被 G1 逐出后失效，每轮尾部重新注入全文。修复方案（run-scoped 标志）已被实验数据支撑。
