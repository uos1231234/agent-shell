# v0.13.1 Plan — Wiki System Agent (code-domain knowledge base)

> **Depends on**: HEAD `206a5be` (v0.13 safety shell + category concurrency + text skill). ADR-018 active. Wiki-mcp literature reference at `本地文学 wiki-mcp`.
> **Blocks**: Future frontend wiki API (this plan documents the contract).

## 0. Goal

Add a **dedicated wiki system agent** to the agent-shell harness that:
1. Connects to a code-domain wiki MCP server (adapted from literature wiki-mcp)
2. Can scan a code repository folder and generate wiki cards (path pointer)
3. Can render wiki entries as Markdown files
4. Is the **only** agent allowed to call wiki-mcp tools (enforced via context injection guard)
5. Exposes high-level operations the working agent can delegate to

## 1. Constraints (7 条)

1. **架构边界**：wiki-mcp server 是独立进程，通过 MCP stdio 连接。不把 wiki 逻辑混入 harness 核心 loop。
2. **安全守卫**：wiki-mcp 工具注册在全局 registry，但 `registry.execute()` 对 wiki-mcp 工具检查 `ctx.isWikiAgent`。仅 wiki agent 可通过。
3. **零外部依赖**：wiki-mcp server 保持零外部依赖（纯 Node.js 内置模块），与 literature wiki-mcp 一致。
4. **领域适配**：类型映射从文学（character/artifact/event/location/organization/concept）改为代码（module/interface/function/class/pattern/concept）。
5. **MD 渲染**：复用 literature wiki-mcp 的 `visualizer/export-md.js` 管线，模板改为代码领域。
6. **前端接口预留**：wiki agent 暴露的工具 schema 即为未来前端 API 的契约，文档中明确标注。
7. **不破坏现有架构**：不改动 warehouse/compressor/recall 的 toolRefs，不改动 MCP/skill 安全壳子（v0.13 已落地）。

## 3. Architecture

### 信息流

```
Working Agent (runIMLoop)
  │
  │  LLM: run_subagent({name:"wiki", input:"scan D:/repo and generate wiki"})
  │
  ▼
Wiki System Agent (createSystemAgent)
  loopOpts.isWikiAgent = true  ← 上下文注入
  loopOpts.toolRefs = [wiki-mcp tools]
  │
  │  LLM: scan_codebase({repo_path:"D:/repo"})
  │       → registry.execute("scan_codebase", args, {isWikiAgent:true})
  │       → 守卫通过 → 执行
  │
  │  LLM: add_card({card:{id:"module-foo", type:"module", ...}})
  │       → registry.execute("add_card", args, {isWikiAgent:true})
  │       → 守卫通过 → 写 data/source/modules.json
  │
  │  LLM: render_md({card_id:"module-foo"})
  │       → 读 data → export-md.js → 写 output/wiki/module-foo.md
  │
  ▼
返回结果给 Working Agent
```

### 上下文注入守卫（registry.execute）

```typescript
// wiki-mcp 工具仅 wiki agent 可调用
const WIKI_TOOL_PREFIX = 'wiki__'
if (name.startsWith(WIKI_TOOL_PREFIX) && !ctx?.isWikiAgent) {
  throw new Error(`Tool "${name}" is restricted to the wiki system agent`)
}
```

### 前端接口预留（Future Frontend API）

Wiki agent 暴露的工具 schema 即为未来前端 REST/WebSocket API 的契约：

| 工具 | 未来前端 API | 方法 |
|---|---|---|
| `wiki__scan_codebase` | `/api/wiki/scan` | POST |
| `wiki__generate_wiki` | `/api/wiki/generate` | POST |
| `wiki__render_md` | `/api/wiki/render/:cardId` | GET |
| `wiki__search_cards` | `/api/wiki/search` | GET |
| `wiki__get_card` | `/api/wiki/cards/:cardId` | GET |

## 4. Principles

1. **wiki-mcp server 是独立进程**——保持 MCP 协议边界，不混入 harness 核心
2. **上下文注入守卫**——不靠接线层约束，靠运行时 ctx.isWikiAgent 校验
3. **零外部依赖**——wiki-mcp server 纯 Node.js，与 literature wiki-mcp 一致
4. **代码领域适配**——类型/关系/渲染模板换领域，核心架构不变
5. **前端契约先行**——工具 schema 即 API 契约，文档明确标注
