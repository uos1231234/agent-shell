## 1. 约束（Constraints，共 8 条）

1. **根因裁决（2026-09-07 用户拍板）**：web-host 工具暴露为空的根因 = 宿主装配遗漏（`git log -S systemToolRefs -- examples/web-host.ts` 全历史零命中），非信号关问题、非前后端通信问题、非库结构错误。修复走"宿主声明 + 库层防御 + 提示词对齐"（用户选 ①+②+③ 全套）。
2. **配置文件归属（用户拍板）**：功能配置（MCP `~/.databus/mcp.json`、子代理 `~/.databus/agents/`、宿主设置 `~/.databus/settings.json`）与凭据配置（`~/.agent-shell/providers.json`）**分开两个家目录**——"功能和配置服务商不是一回事，分开才是解耦且内聚的"。不迁移、不统一。
3. **子代理向下配置开关作用域（用户拍板）**：全局开关、新会话生效（attachSession 时读一次注入 toolPolicy）；运行中会话不变，与"注册是启动期行为"（ADR-018 D6）一致。
4. **渐进式披露不回退（v0.18）**：systemToolRefs 是显式白名单，不是"注册即暴露"。`record_m3_summary`（compressor 专用）永不进工作代理清单。MCP/skill 工具仍走 `load_tools` 动态加载。
5. **信号关唯一中转（ADR-026）**：新设置命令全走 Gate 命令通道（`/api/v1/cmd`），不新增 HTTP 路由，不加出站信号 kind（设置面板是请求-应答，不需要出站流）。
6. **ADR-015**：不新增 guard/metric/config 字段。settings.json 是宿主配置文件，不进 ShellConfig。
7. **optional-handler 模式（v0.23 provider 先例）**：`handlers.mcp` / `handlers.subagent` / `handlers.extensions` 全部 optional，未装配时干净报错，既有测试不破；gate.ts 穷尽性 switch 强制路由。
8. **当前基线：库 1812 tests 绿 / tsc 0 错；webapp 15 tests 绿 / tsc 0 错。完成后不得回退。**

## 3. 架构信息（Architecture）

```
真 LLM 工具链路（Wave A 修复后）：
  web-host attachSession
    ├─ createBuiltinTools({cwd})                    内置 15 工具注册
    ├─ new Mailbox()（每会话一个——修"每轮 new"隐患）
    ├─ createSystemAgents({llmStreamChat,url,model,mailbox,registry,stateLine})
    ├─ createSubAgentRegistry({diskDir,registry,toolPolicy: 开关产物})
    │    └─ agentTree.rebindRoot({rootId:'main', sessionId})
    ├─ registerSystemAgentTools(...)                系统工具注册
    ├─ refs = registry.listSystemTools().filter(≠record_m3_summary)
    ├─ buildStaticPrompt({exposedSystemToolRefs: refs})   ③ 提示词=暴露清单
    └─ runPrompt → buildLoopOptions({systemToolRefs: refs, mailbox, ...})
         └─ composePrompt → tools 数组有货 → LLM 可真正发起工具调用  ①

  session-manager buildLoopOptions（②）：
    systemToolRefs 为空 && registry.listSystemTools().length > 0
      → logger.warn 一次（per-session 幂等）

Wave B 设置数据流（与 v0.23 provider 同构）：
  设置面板 ──REST /api/v1/cmd──▶ Signal Gate ──▶ handlers.mcp/subagent/extensions（web-host）
                                                  ├─ mcp:    ~/.databus/mcp.json 读写（启动期 boot，重启生效）
                                                  ├─ subagent: ~/.databus/agents/*.json + settings.json 开关（新会话生效）
                                                  └─ extensions.info: 已加载清单（skills/servers，来自宿主启动状态）
```

**MCP 连接生命周期**：宿主启动时读 mcp.json → `connectToServer` 逐个连接（fail-fast，失败全关）→ 连接常驻宿主；每会话 attachSession 时 `registerMcpConnection(sessionRegistry, conn)` + `registerMCPServerMeta` 把工具登记进会话 registry（execute 闭包捕获共享连接，审批 door 按 sessionId 隔离不受影响）。**不在每会话重复 spawn MCP 进程。**

## 4. 设计原则（Principles）

1. **白名单事实源单一**：refs 数组只算一次（registerSystemAgentTools 之后），同源喂给 buildStaticPrompt 和 buildLoopOptions——提示词宣传 = 模型实际拿到。
2. **告警不阻断**：空 refs 是合法意图（纯聊天代理），warn 一次足矣；throw 会破坏合法场景。
3. **配置文件各自内聚**：mcp.json 管 MCP、agents/*.json 管子代理、settings.json 管宿主开关与目录——一个文件一个关注点，写服务复用 v0.23 原子写模式（tmp+rename+.bak）。
4. **写入前必须校验**：mcp.upsert 走 `validateMcpServerConfig`；subagent.upsert 走 `validateSubAgentConfig`（toolRefs 必须在参考 registry 里真实存在）。
5. **开关即 policy 注入**：向下开关 ON = toolPolicy 规则表去掉 `run_subagent`/`define_subagent` 两条 deny（其余 deny——bash/write/edit/record_m3_summary——保留），深度守卫（maxSubAgentDepth=3）兜底防无限递归。
6. **MCP 连接宿主级共享、注册会话级隔离**：连接是进程句柄（贵），注册是 registry 条目（便宜）。

## 7. 决策信息（Decisions）

**已决定（用户拍板 2026-09-07）**：
- 修复范围 ①+②+③ 全套（宿主声明 + 空清单告警 + 提示词对齐）。
- 配置归属：功能配置（~/.databus）与凭据（~/.agent-shell）分开——解耦且内聚。
- 向下开关：全局、新会话生效。

**实现内自主决定（不另行请示）**：
- refs 排除清单 = `['record_m3_summary']`（compressor 专用，唯一确定不该暴露的系统工具）。
- 告警用 `defaultLogger.child({component:'session-manager'})`，遵守 ADR-020 必保事件纪律补充。
- settings.json 读写失败 fail-fast（throw 干净错误），与 providers.json 纪律一致。

**未决 / 后续版本**：
- driveCoordinator 在 web-host 仍是 noop（M1/M2 压缩不在本计划范围）。
- Skill 文件本身的在线编辑（面板只管目录与清单）。
