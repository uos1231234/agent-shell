## 0. Goal

Land v0.14 as a **governance remediation release**: address the five high-priority issues
left open by the v0.13 review that observability (v0.14-pre) surfaced or made observable.
The release establishes three new invariants and is the smallest set of code changes that:

1. **Captures the observability contract as ADR-020** — every harness subsystem must emit
   at least one structured log record per discrete work unit; log points become a review checklist.
2. **Closes the MCP stdio env-leak vector (P0-2)** — `getDefaultEnvironment()` no longer reaches
   user-spawned MCP subprocesses; only an explicit whitelist is forwarded.
3. **Closes the turn.id collision latent bug (P1-1)** — `Math.random().toString(36).slice(2)`
   becomes `crypto.randomUUID()` everywhere a new turn id is minted.
4. **Makes magic numbers configurable (P2-1)** — `MEMORY_LAYER_THRESHOLDS` (200K/500K/900K)
   and `MAX_SUB_AGENT_DEPTH` (=3) move from module-level constants into caller-supplied config.
5. **Exposes `Logger` as a public API (P3-1)** — `src/index.ts` re-exports `Logger`/`defaultLogger`/
   `setLevel`/`setSink` so external callers (宿主应用, custom frontends) can wire the harness's
   logs into their own sinks without monkey-patching module globals.

## 1. Constraints (5 条)

1. **Observability first** — no refactor is allowed to delete or weaken a logger call site
   introduced in v0.14-pre (working tree: `src/im/loop.ts`, `src/im/system-agents/drive-coordinator.ts`).
   New logger calls are encouraged, removing existing ones is forbidden in this release.
2. **No new external deps** — env whitelist uses literal string allow-list (no `dotenv`/`lodash.pick`).
   crypto.randomUUID is a Node 22 built-in (already a devDep upper bound).
3. **Atomic config migration** — `MEMORY_LAYER_THRESHOLDS` values move but **only when the caller
   passes a `MemoryConfig`**. Default is the same three numbers; existing callers see no change.
4. **Backward-compatible exports** — `src/index.ts` may ADD re-exports; renaming or moving
   existing imports (`./im/loop.js`, etc.) is forbidden.
5. **Subagent task boundary** — three independent workstreams (env whitelist / turn.id / config
   magic numbers / public API export) MUST land in three separate commits so any one can be
   reverted without re-opening the others. The shared logger additions (§6.4) are part of
   subagent-1's scope to keep the env-whitelist tests in one file.

## 4. Design principles

1. **Whitelist > opt-out for env** — `getDefaultEnvironment()` is opt-out by default (you have
   to know to pass `env: {}` to remove vars). We replace it with opt-in (you have to know what
   you want). This eliminates the entire class of "secret leaked to MCP subprocess" bugs.
2. **UUIDs everywhere a stamp is minted** — `crypto.randomUUID()` is collision-free and Node-
   native. `Math.random().toString(36).slice(2,8)` is 6 chars of base36 entropy; in a 6-tool
   batch the birthday-paradox collision probability is ~1 in 47k. Replace everywhere.
3. **Config-as-data, not module constants** — magic numbers that callers might want to tune
   (`MEMORY_LAYER_THRESHOLDS`, `MAX_SUB_AGENT_DEPTH`) move into `MemoryConfig` and `ShellConfig`
   respectively. Defaults match current values exactly. Existing call sites that omit these
   fields get the same behaviour they had before.
4. **`MemoryConfig` is a separate type, not a field on `ShellConfig`** — ShellConfig is about
   runtime guards (token / iter / toolRate / time / errorRate). MemoryConfig is about
   information-flow layering. Mixing them couples unrelated concerns and breaks the ADR-003
   rule "shell has no business fields". The new type lives at `src/shell/memory-config.ts`
   so the shell layer owns it (the layered projection is a shell concern).
5. **Public API is additive only** — `src/index.ts` (new file) re-exports the existing internals
   callers might want AND the new logger symbols. Existing imports (`./im/loop.js`,
   `./shell/registry.js`) continue to work; the new file is sugar, not a replacement.

### 5.5 MCP stdio env whitelist (in `src/mcp/connection.ts`)

```ts
// v0.14 P0-2: only forward well-known safe variables to MCP stdio subprocesses.
// Secret-bearing env vars (ARK_KEY, OPENAI_API_KEY, AWS_*, etc.) MUST NOT be
// forwarded unless explicitly listed in cfg.env. This replaces the prior
// { ...getDefaultEnvironment(), ...cfg.env } merge which leaked the parent
// process's env wholesale.
const SAFE_ENV_VARS = ['PATH', 'Path', 'HOME', 'HOMEPATH', 'USERPROFILE',
                       'LANG', 'LANGUAGE', 'LC_ALL', 'TZ',
                       'TMPDIR', 'TMP', 'TEMP'] as const
function buildSafeEnv(cfgEnv?: Record<string, string>): Record<string, string> {
  const out: Record<string, string> = {}
  const sys = process.env as Record<string, string | undefined>
  for (const k of SAFE_ENV_VARS) {
    if (sys[k] !== undefined) out[k] = sys[k]
  }
  if (cfgEnv) Object.assign(out, cfgEnv)
  return out
}
```

### 6.4 Shared logger convention for all subagents

- Always `(opts.logger ?? defaultLogger).child({ component, ... })` at module init / loop start.
- Auto-fields: `ts` (Date.now), `level` (caller cannot override), `msg`.
- Bindings via `child({...})` accumulate; caller-field conflicts follow pino convention
  (caller wins), but `level`/`ts`/`msg` are emit-owned (covered by tests/shared/logger.test.ts).
- Default sink is `process.stderr` NDJSON. Test fixtures install `setSink(() => {})` in
  `beforeEach` and restore in `afterEach` to avoid stderr pollution.
