## 4. 设计原则（Principles）

1. **压缩来自结构化，不来自删减事实**（D10 / 铁律）：G1 信封保留完整结论，压缩率只来自丢弃输入材料。本补丁不改这个原则，只调阈值。

2. **阈值调优 = 实验驱动，不是拍脑袋**：用户明确要求"做实验验证 5K/10K 压缩效果"。计划先跑实验，根据数据定阈值，不预设答案。

3. **userTemplate 修复 = 最小语义修正**：只改去重判据，不改 composePrompt 的组装顺序，不改 loop 入口的 canonical 写入逻辑。

4. **向后兼容**：goal 未激活时行为逐字节不变（既有测试零修改通过 = 硬判据）。

### 5.2 userTemplate 去重修复

**改动文件**：
- `src/im/loop.ts:290-294`：`omitUserTemplatePart` 函数，改去重判据

**方案 B（推荐）**：
```ts
// 改前：
function omitUserTemplatePart(turns: readonly ConversationTurn[], userTemplate: string): boolean {
  if (userTemplate === '') return false
  return turns.some(t => t.role === 'user' && typeof t.content === 'string' && t.content === userTemplate)
}

// 改后：
function omitUserTemplatePart(turns: readonly ConversationTurn[], userTemplate: string): boolean {
  if (userTemplate === '') return false
  // goal- 信封包含用户文本的摘要（#OBJECTIVE），canonical 里有 goal- = 用户文本已存在
  return turns.some(t =>
    t.role === 'user' &&
    t.id.startsWith('goal-')
  ) || turns.some(t =>
    t.role === 'user' &&
    typeof t.content === 'string' &&
    t.content === userTemplate
  )
}
```

**语义**：
- goal 模式下：canonical 里有 `goal-<uuid>` 回合 → 跳过 userTemplate（用户文本已在某处存在）
- 非 goal 模式：无 `goal-` 回合 → 走原有 `content===userTemplate` 判据（行为不变）
- 边缘场景：用户在 goal- 之后又手动发消息 → goal- 不在末位，但判据仍命中（存在性检查）→ 跳过 userTemplate。此时 goal 条件大概率已达成（否则 harness 续跑），重注入一次用户文本的代价可接受。

**备选方案 C**（更严谨）：只在末条是 goal- 时跳过。优点：最严格；缺点：中间插入其他消息时失效。**不推荐**——概率极低且收益小。
