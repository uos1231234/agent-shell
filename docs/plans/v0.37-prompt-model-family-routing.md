## 0. 问题核实结论（上一版为什么不合格）

上一版变体（另一个会话产出，+199 行，零测试）逐条核实结论——**三条全部属实**：

| # | 问题 | 证据 |
|---|---|---|
| P0-1 | **死代码**：路由有一个永不满足的输入 | `assembly.ts:772` 的 `buildStaticPrompt({ mode, agentName, registry, exposedSystemToolRefs, promptInjectionDefense, workDir })` **不含 `modelId`** → `opts.modelId` 恒 `undefined` → `selectPromptTemplate` 的 deepseek / glm 分支不可达 → 两个变体常量（148 行）**零生产消费者** |
| P0-2 | **契约丢失**：架构/记忆两节消失 | `# Architecture Management`（ARCHITECTURE.md 模板 + 更新时机）与 `# Memory Management`（MEMORY.md 索引规则 + ADR 六段规范）只在 `FULL_PROMPT_TEMPLATE` 里；变体区间实测 grep **零命中**。注入源 `injections/{memory,architecture}.ts` 只 `return content` 裸贴文件内容，**不带维护指令**，兜不住 |
| P0-3 | **安全规则被削** | 变体 Safety 段 7 → 5（DeepSeek）/ 4（GLM）条，丢掉"后台命令必须前台 + timeout 并清理（`list_processes`/`kill_process`）"与"不改生产配置"；通用模板的 "do not delete based on your own judgment" 被弱化为只留"获得授权" |
| P1 | 重复三份、零测试、版本号矛盾 | Safety / Coding Principles / Tool Usage Guide / Communication Style 各写 3 份；`selectPromptTemplate` 等在 `tests/` 零命中；`static-prompt.ts` 标 v0.31 而 `section-builder.ts` 标 v0.37，且 CODE_MAP/DECISIONS 无 v0.37 任何记录 |

**根因**：变体是**从通用模板复制后改**的派生副本。源改了副本不知道 → 漏段落、削安全是结构必然，不是手滑。（MiMoCode 的变体是各自**完整自足**的独立 `.txt`，因此不丢段落，但代价是改一处要改 N 份——两种做法各有病，我们选第三种。）

## 1. 约束（Constraints）

1. **不碰状态机**：本改动只涉及 `src/im/prompt/` 与宿主装配层的一行参数，不涉及 guard / 上下文组装顺序 / loop 主循环。
2. **前后端只走信号关**：本改动不涉及前端，不新增任何直连通道。
3. **工具双披露保留**（用户 2026-09-12）：`{tooling_section}` 清单（提示词）+ 工具 schema（payload）两处披露是刻意设计，不因变体而改变。
4. **安全设计保留**：变体不得影响任何安全条目。
5. **文件注入与维护机制保留**：`MEMORY.md` / `ARCHITECTURE.md` 的注入与维护契约必须对所有模型族生效。

```
              ┌──────────────────────────────────────────────────────┐
  modelId ──▶ │ FULL_PROMPT_TEMPLATE —— 唯一基底，只写一份            │
  正则路由     │                                                      │
  (子串匹配)   │  {persona_section}          ← 槽位① 按模型族注入      │
              │  # Safety Rules (7 条) ─────────────┐                 │

              │  # Code-Information-Driven ─────────┤ 全族共用        │
              │  # Tool Usage Guide {tooling_section}（双披露）──┤     │

              │  # Action Strategy ─────────────────┤                 │

              │  {dynamic_sections}  ← ContextInjector 运行时位置      │

  路由表（resolvePromptVariants）
  ┌──────────────────┬────────────────────────┬──────────────────────────┐
```

`resolvePromptVariants` → 填槽 → 系统提示词 → `gate.emit('session.event', 'system.prompt')`。

## 4. 设计原则（Principles）

1. **基底唯一**：模型族差异只允许出现在两个槽位；其余段落没有第二个副本。
2. **占位符即位置**：位置声明在模板里，匹配逻辑不认识位置。
3. **降级而非报错**：未命中的 id 回落通用段，绝不让提示词因命名问题导致会话不可用。
4. **照搬文本、剥掉环境**：外部素材必须改写掉一切宿主专属约束（工具名、包管理器、项目文件）。
5. **可检查胜过可计数**：不引入无依据的数字阈值；边界写成条件式规则。
6. **安全不因族而异**：若某族需要不同安全策略，改唯一那份（全族生效），不开副本。

### 7.2 实现期发现（计划未预见）

1. **通用段升级会改变所有模型的默认行为**——不只是 DeepSeek/GLM。这是刻意选择（未命中族一并受益），但影响面比"只改两族"大，实施前已向用户确认。
2. **`FULL_PROMPT_TEMPLATE` 不再直接含 `{agent_name}`**（它随 persona 段进入）→ 既有断言需要同步，否则会误报回归。已在 `static-prompt.test.ts` 更新并注明原因。
3. **模型 id 判定出现第二处实现**（`config/model-capabilities.ts` 的 `KNOWN_MODELS` 是前缀正则，本处是子串）。两者语义不同（判能力 vs 判人格），规模小，暂不统一——已记入 ADR-033 Consequences。
