## 3. 架构思想（本计划 specific 的取舍）

1. **默认更受限，但显式可配置**。子智能体工具权限默认 allow + 黑名单（保持向后兼容），但调用方可以通过 `SubAgentToolPolicy` 收紧到默认 deny 或按命名空间 deny。这是 v0.11.2 的折中；v0.12 再评估是否默认 deny。
2. **类型诚实**。`ctx.databus` 的运行时类型应与其使用方式一致；单元素数组不包装成 `MultiDatabus`。
3. **测试覆盖真实链路**。特别是 working agent 的 `runIMLoop` 真正发出 `run_subagent` tool_call 并被执行的完整路径。
4. **异步写盘可观测**。`register()` 返回 `Promise<void>`，失败真实 reject，调用方可以选择 await。
5. **身份命名空间隔离**。系统保留名（`databus`、`system`、`drive-coordinator`、`warehouse`、`compressor`、`recall`、`main`）从子智能体名源头禁止，而不是只在 mailbox 层兜底。
6. **单一职责**。权限策略独立为 `policy.ts`；`driveCoordinator` 只是透传参数，不侵入子智能体逻辑。

## 5. 模块引导（新文件 / 修改文件 / API）

### 5.1 新增 `src/im/sub-agent/policy.ts`

```typescript
// SubAgentToolPolicy: declarative, extensible permission policy for sub-agents.
// Replaces the hardcoded SUB_AGENT_FORBIDDEN_TOOLS / SUB_AGENT_PRIVILEGED_TOOLS
// sets so that future skills/MCP servers can be controlled by namespace rules.

export type ToolPolicyRule = {
  mode: 'allow' | 'deny'
  // Exact tool ref, or a glob with a single '*' wildcard.
  // Examples: 'bash', 'dangerous-server__*', 'my-skill__*'.
  pattern: string
}

export type SubAgentToolPolicy = {
  description?: string
  default: 'allow' | 'deny'
  rules: ToolPolicyRule[]
}

// Backward-compatible default: allow all registered tools except the ones
// historically restricted in v0.11.1. Callers can pass a stricter policy.
export const DEFAULT_SUB_AGENT_TOOL_POLICY: SubAgentToolPolicy = {
  default: 'allow',
  rules: [
    { mode: 'deny', pattern: 'run_subagent' },
    { mode: 'deny', pattern: 'define_subagent' },
    { mode: 'deny', pattern: 'record_curated_block' },
    { mode: 'deny', pattern: 'record_m3_summary' },
    { mode: 'deny', pattern: 'bash' },
    { mode: 'deny', pattern: 'powershell' },
    { mode: 'deny', pattern: 'write' },
    { mode: 'deny', pattern: 'edit' },
  ],
}

export const applyToolPolicy = (toolRef: string, policy: SubAgentToolPolicy): boolean => {
  let allowed = policy.default === 'allow'
  for (const rule of policy.rules) {
    if (matchesPattern(rule.pattern, toolRef)) {
      allowed = rule.mode === 'allow'
    }
  }
  return allowed
}

const matchesPattern = (pattern: string, ref: string): boolean => {
  if (pattern === ref) return true
  const star = pattern.indexOf('*')
  if (star === -1) return false
  const prefix = pattern.slice(0, star)
  const suffix = pattern.slice(star + 1)
  return ref.startsWith(prefix) && ref.endsWith(suffix)
}
```

  let ctxDatabus: Databus | MultiDatabus | undefined
  if (opts.ctxDatabus === undefined) {
    ctxDatabus = undefined
  } else if (Array.isArray(opts.ctxDatabus)) {

## 9. 风险与回滚

| 风险 | 缓解 |
|---|---|
| `register()` 改为 async 导致上游 break | 只影响工作区内的调用点（define-subagent、loadFromDisk、测试），全部同步更新 |
| policy 默认行为与 v0.11.1 不一致 | 默认 policy 保持 v0.11.1 的 allow + 黑名单，不 break 现有测试 |
| driveCoordinator 接线引入复杂依赖 | harness 里使用现有 `createSystemAgents` 工厂，不新建 system agent 逻辑 |
| 单元素不包 MultiDatabus 后某些测试依赖 MultiDatabus 类型 | 只在明确多 bus 场景中断言 MultiDatabus；单 bus 场景不依赖具体类 |

**回滚**：如果某阶段失败且 2 次尝试无法解决，停止并报告，不强行推进到下一阶段。
