## 0. 约束（不可违反）

1. **不引入新依赖**——Node.js 内置 + 现有 `glob`。
2. **每次修改后跑 `npx tsc --noEmit` + `npx vitest run`**，全绿才下一步。
3. **不删除现有测试**——只修改或新增。
4. **保持 v0.11.2 向后兼容**，除非明确要 break（如 `record_curated_block` 移除 LLM layer 参数）。
5. **API key 永远不进源码**，包括默认值、注释中的 key、测试 fixture。
6. **所有改动在 `agent-shell/` 内**。

### P0-1【安全】API key 硬编码

**现状**：`examples/real-llm-monitor.ts:32` 和 `examples/real-corpus-compression.ts:48` 把 `ARK_KEY` 默认值写成源码。

**根治**（接口/配置层面）：

- 在文件顶部加永久注释：
  ```typescript
  // SECURITY: ARK_KEY must be provided via environment variable.
  ```

**是否清洗 git 历史**：本计划只改工作区文件；如果仓库未来 push 到远端，必须再做 `git filter-repo` 或等效历史清洗。

### P0-2【G4 假完成】`SubAgentToolPolicy` 没有调用入口

**现状**：`validateSubAgentConfig` 接受 `toolPolicy`，但 `define_subagent`、`register()`、`loadFromDisk()` 都不传它，导致扩展点死亡。

**根治**（接口层）：

```typescript
// src/im/sub-agent/registry.ts
export class SubAgentRegistry {
  constructor(
    registry?: ToolRegistry,
    // P0-2: policy injected at registry creation; flows to all config paths.
    private readonly toolPolicy: SubAgentToolPolicy = DEFAULT_SUB_AGENT_TOOL_POLICY,
  ) {}

  async register(cfg: SubAgentConfig, diskDir?: string): Promise<void> {
    const validated = this.registry
      ? validateSubAgentConfig(cfg, this.registry, { toolPolicy: this.toolPolicy })
      : cfg
    ...
  }

  async loadFromDisk(dir: string, registry: ToolRegistry): Promise<number> {
    ...
    const cfg = validateSubAgentConfig(parsed, registry, { toolPolicy: this.toolPolicy })
    ...
  }
}

// src/im/tools/define-subagent.ts
export const createDefineSubagentTool = (
  subAgentRegistry: SubAgentRegistry,  // registry already carries policy
  registry: ToolRegistry,
  diskDir?: string,
): SystemTool => ({
  ...
  execute: wrapTool('define_subagent', async (args) => {
    const cfg = validateSubAgentConfig(..., registry, {
      toolPolicy: subAgentRegistry.toolPolicy,  // 或者让 register 内部自己用 policy，这里不传也行
    })
    await subAgentRegistry.register(cfg, diskDir)
    ...
  }),
})
```

更优雅的版本：**SubAgentRegistry 自己持有 policy，调用方只需要构造时传入一次**。`define_subagent` 的 `validateSubAgentConfig` 调用可以简化为只调 `subAgentRegistry.register()`（register 内部会 validate）。这样 policy 不暴露给 define-subagent。

```typescript
// define-subagent.ts
const cfg: SubAgentConfig = { name, systemPrompt, toolRefs, config }
await subAgentRegistry.register(cfg, diskDir)  // register 内部验证 + 写盘
```

这样 `SubAgentRegistry` 成为 policy 的**单一拥有者**：构造时注入，register/loadFromDisk 都使用它。调用者（harness / application）在创建 `SubAgentRegistry` 时决定策略。

**向后兼容**：不传 policy 时默认 `DEFAULT_SUB_AGENT_TOOL_POLICY`，与 v0.11.2 行为一致。

**新增测试**：
- `SubAgentRegistry` 构造时传入自定义 policy，验证 `register()` 和 `loadFromDisk()` 都按自定义策略执行。
- `define_subagent` 工具通过 registry 间接应用自定义策略。

### P1-1【隐含边界 I1】子智能体熔断可观测性

**现状**：`run_subagent` 只返回 `output` 字符串；子智能体 guard-tripped 时与"正常无输出"无法区分。

**根治**（接口层）：

定义结构化返回类型，让 working agent 能看到状态而不泄露内部细节：

```typescript
// src/im/tools/run-subagent.ts
export type SubAgentRunResult = {
  output: string
  status: 'completed' | 'guard-tripped'
  // Optional machine-readable hint for the parent agent.
  // Does NOT expose guard internals beyond the guard id.
  trippedHint?: 'iter' | 'token' | 'toolRate' | 'time' | 'errorRate'
}
```

工具 execute 返回该对象，`executeToolCalls` 会自动 `JSON.stringify` 它，所以 working agent 的 tool result 是：

```json
{ "output": "review complete", "status": "completed" }
```

或熔断时：

```json
{ "output": "", "status": "guard-tripped", "trippedHint": "errorRate" }
```

实现要点：

```typescript
// run-subagent.ts execute
const result = await agent.run({ messages: [...] })
const output = lastTurn?.role === 'assistant' ? (lastTurn.content ?? '') : ''

if (result.reason === 'guard-tripped' || result.finalState === 'Tripped') {
  const hint = result.hits[0]?.id // 'errorRate' | 'iterGuard' | ...
  return {
    output,
    status: 'guard-tripped',
    trippedHint: sanitizeGuardId(hint),
  }
}
return { output: output || '(sub-agent produced no output)', status: 'completed' }
```

其中 `sanitizeGuardId` 只暴露计划内的 guard id（`iterGuard` 映射为 `'iter'` 等），不暴露内部字段。

**测试更新**：
- `run-subagent.test.ts` 中期望字符串的断言改为期望对象。
- 新增测试：子智能体触发 guard 时返回 `status: 'guard-tripped'`。
- `loop-run-subagent.test.ts`（G1）断言 tool result JSON 含 `status`。

### P1-2【隐含边界 I2】`MultiDatabus.subscribe` 不做 id 去重

**现状**：`subscribe()` 直接聚合底层 bus 回调；若未来同一 turn 投影到多个 bus，会重复投递。

**根治**（接口层）：

`MultiDatabus.subscribe` 对回调做 id 去重包装：

```typescript
subscribe(sourceAgentId: AgentId | '*', onEvent: (turn: ToolTurn) => void): () => void {
  const seen = new Set<string>()
  const wrapped = (turn: ToolTurn): void => {
    if (seen.has(turn.id)) return
    seen.add(turn.id)
    onEvent(turn)
  }
  const unsubs = this.buses.map(b => b.subscribe(sourceAgentId, wrapped))
  return () => unsubs.forEach(u => u())
}
```

`seen` 随订阅回调一起释放，unsubscribe 后 GC，无长期内存泄漏。

**新增测试**：
- 构造两个底层 bus，把**同一个 ToolTurn 对象** append 到两个 bus，订阅 '*' 应只收到一次回调。
- unsubscribe 后重新订阅，id 集合隔离（新订阅不受旧 seen 影响）。

### P1-3【隐含边界 I3】M1/M2 zone 分层的信任边界

**现状**：`record_curated_block` 的 `layer` 优先级是"LLM 显式 arg > ctx.compressZone > 'M1'"，意味着 compressor LLM 可覆盖 drive-coordinator 的正确 zone。

**根治**（接口层）：**zone 是调用上下文，不应由 LLM 覆盖**。`record_curated_block` 不再暴露 `layer` 参数给 LLM，layer 完全来自 `ctx.compressZone`。

```typescript
// record-curated-block.ts
parameters: {
  block: { ... },
  // layer REMOVED from LLM-facing schema
  reason: reasonField,
}

execute: wrapTool('record_curated_block', async (args, ctx) => {
  ...
  const layer = ctx?.compressZone ?? 'M1'
  await sl.compressor.appendBlock(a.block, layer)
  return { ok: true, layer }
})
```

这样：
- drive-coordinator 根据 estimatedTokens 决定 zone → 通过 `metadata.zone` 传 → `system-agent.ts` 注入 `loopOpts.compressZone` → `record_curated_block` 使用。
- LLM 无法误导 layer，M1/M2 语义完全由调用方权威决定。

**向后兼容影响**：`record_curated_block` 的 schema 删除 `layer` 参数，但 v0.11.2 才引入的 LLM layer 参数使用场景极少（compressor prompt 不应主动传它），可以接受。

**测试更新**：
- `compress-zone.test.ts` 中"LLM 显式传 layer 覆盖"的测试删除或改为"忽略 LLM layer，使用 ctx.compressZone"。
- 新增测试：无 ctx.compressZone 时默认 M1；ctx.compressZone='M2' 时 state-line 收到 M2。

## 4. 边界说明

### S1 边界保持现状

子智能体可实时订阅 working agent 事件流——用户已确认符合设计，本计划不改动。

### policy 默认姿态

`DEFAULT_SUB_AGENT_TOOL_POLICY` 保持 `default: 'allow'` + deny 黑名单，确保 v0.11.2 行为不变。调用方可在创建 `SubAgentRegistry` 时传入 `default: 'deny'` 收紧。

### zone 权威来源

压缩 zone 的唯一权威是 drive-coordinator 根据 `estimatedTokens` 判断出的 `metadata.zone`。LLM 不再能覆盖。

## 6. 风险与回滚

| 风险 | 缓解 |
|---|---|
| `record_curated_block` 移除 `layer` 参数影响 compressor prompt | 检查 compressor prompt 是否依赖 LLM 传 layer；若依赖，改为 prompt 中不期望该参数 |
| `SubAgentRunResult` 返回对象影响下游解析 | `executeToolCalls` 自动 JSON.stringify，下游读取 JSON 即可；旧纯文本测试更新断言 |
| corpus-converter 移动后 scripts cjs 引用失败 | 移动后跑 `npx tsc --noEmit` 会捕获路径错误 |
| policy 默认变化 | 默认策略保持 v0.11.2，不变化 |

**回滚**：任一阶段失败且 2 次尝试无法解决，停止并报告。
