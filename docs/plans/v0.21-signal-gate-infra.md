## 1. 约束（Constraints）

本段引用不可违反的既有决策与代码事实（均 [已验证] 读源码）：

1. **核心哲学第 6 条**（ARCHITECTURE.md "Hook philosophy"，用户拍板 2026-09-05）：hook 是 harness 自身的信息流接缝，**不是第三方插件 API**，本 harness 不做面向外部的扩展系统。→ Signal Gate 是 harness 自身的中间层，不是插件市场。
2. **不把前端耦合进状态机**（用户拍板多次）：前端与状态机之间只允许信号关系，Signal Gate 是唯一双向中转站。**loop.ts 的上下文工程（compose / projection / canonical conversation）不得被前端需求侵入。**
3. **ADR-020 必保事件清单**：runIMLoop 的 start/completed/guard tripped/protocol error/shell terminated 等事件已固化，Signal Gate 只能新增消费者，不得改动这些事件语义。
4. **ADR-015**：不新增 guard/metric/config 字段；Signal Gate 不是 guard，不做熔断统计，走既有事件/错误流。
5. **审批现状是 fail-closed stub**（`src/extensions.ts:210-220`，注释明说 "TODO: wire up the actual handler"）：`approvalHandler?: ApprovalHandler` 已在 API 面，默认 handler 直接 `return 'rejected'`。→ v0.21 不新增审批机制，只把默认 stub 换成"经 Signal Gate 问前端"的 handler。
6. **渲染基座三件套 per-session 隔离**（`src/extensions.ts:84-89, 125-129` + `src/im/session/types.ts:154-158`）：bus/base/store 每会话独立，防跨会话 artifact 泄漏。Signal Gate 必须尊重这个隔离。
7. **用户已拍板（2026-09-06）**：
   - Signal Gate 与 web 服务层**分开**：Gate = 进程内纯内存总线（可独立测试、可被 CLI/未来 ACP 复用）；web 层 = 把它暴露成 WS/REST，前端只连 web 层。
   - **前端 webapp 独立目录同仓**（`webapp/`，与 agent-shell 同仓但独立构建）。
   - **本计划不做任何前端页面**（连"验证前端"都不做）；前端完整 UI 归 v0.22，由具备视觉能力的模型执行。
   - 前端要有**日志界面**（便于用户审查）→ 本计划需提供"日志出站信号"（logger setSink → Gate → 前端），渲染归 v0.22。

## 3. 架构信息（Architecture）

```
┌─────────────────────────────────────────────────────────────────┐
│ v0.22 前端 React SPA (webapp/ 独立同仓)                           │
│   只连 Web 层契约（WS 事件流 + REST 指令）                        │
└───────────────▲──────────────────────────────────────────┘
                │ ③ WS/REST
┌───────────────┴──────────────────────────────────────────┐
│ Web 服务层 (本计划, src/webshell/)                           │
│   http (静态+指令) + ws@8 (事件流)                          │
│   bearer token(fragment) · 内存 seq 游标(越界全量重拉)       │
│   订阅 Gate 出站 → 推前端 · 收前端指令 → Gate.command()      │
└───────────────▲──────────────────────────────────────────┘
                │ ② Gate 进程内 API
┌───────────────┴──────────────────────────────────────────┐
│ Signal Gate (本计划, src/signals/ 纯内存总线)                 │
│   出站 emit/on · 请求 request/resolve · 入站 command        │
│   ↓ 渲染基座 = Gate 内部一级（bus 先给 Gate 再转发基座）      │
└───────────────▲───────────────────────────────────────────┘
                │ ① 订阅既有挂点（接线器，见 §5.2）
┌───────────────┴──────────────────────────────────────────┐
│ agent-shell 状态机 (几乎不动)                                │
│   · call.ts 加 onStreamChunk 出站口（token delta）          │
│   · approvalHandler stub → Gate handler                    │
└───────────────────────────────────────────────────────────┘
```

**信号分类**：
- **出站事件**（后端→前端，fire-and-forget）：`assistant.delta` / `thinking.delta` / `tool.started` / `tool.result` / `artifact` / `turn.end` / `session.event`（HookSystem 三事件）/ `memory.activity`（压缩/M3 进度）/ `log`（日志，全局审查）
- **入站命令**（前端→后端，需回执）：`user.prompt` / `session.create|open|close|delete|list` / `turn.cancel` / `permission.revoke|full` / `approval.decision` / `ask_user.answer`
- **请求-应答**（后端挂起等前端）：`approval`（审批）、`ask_user`（提问）、未来 `pre_tool_use`（可否决）

## 4. 设计原则（Principles）

1. **Signal Gate 是 harness 自身的中间层，不是插件系统**。收编 harness 自己 18 个"需要与人交互"挂点；前端通道从它进出；不制造第三方插件 API。
2. **单向依赖**：状态机不认识 Gate，它只是"有挂点"；Gate 主动订阅。Gate 对状态机的全部改动 = call.ts delta 出站口 + approval stub 换 handler。
3. **渲染基座降级为 Gate 的一级**：RenderingSignalBus 先给 Gate，Gate 再转发基座。基座内部实现（renderMarkdown/ArtifactStore/onArtifact）不变。
4. **出站事件 vs 入站命令 vs 请求-应答 严格三分**（见 §3）。审批是特殊的"阻塞式双向"，带超时 fail-closed。
5. **token 级 delta 是唯一触碰 shell 代码的点**，用"包装 streamChat / call.ts 加可选回调"而非改写聚合逻辑——保持 protocol/shell 纯净。
6. **Web 层只做翻译，不含业务**：把 Gate 信号变 WS 帧、把 WS 指令变 Gate.command。所有"该不该、怎么答"逻辑在 Gate/状态机侧。
7. **依赖边界分明**：Web 层做 WS 用 `ws`（官方/业界同款，见 §7 #1），HTTP 用 node:http 不引框架；静态托管同端口挂 fallback。**库核心（signals/im/shell/protocol）保持零外部运行时依赖**——`ws` 只进应用侧 webshell。

### 5.1 Signal Gate — `src/signals/`（新增，纯内存，零 I/O）

```
src/signals/
```

```ts
// types.ts（示意，不写全）
export type GateSignal =                       // 出站事件
  | { kind: 'assistant.delta'; sessionId: string; turnId: string; text: string }
  | { kind: 'thinking.delta'; sessionId: string; turnId: string; text: string }
  | { kind: 'tool.started';  sessionId: string; turnId: string; toolName: string; callId: string; args: unknown }
  | { kind: 'tool.result';   sessionId: string; turnId: string; toolName: string; callId: string; result: unknown }
  | { kind: 'artifact';      sessionId: string; handle: ArtifactHandle }
  | { kind: 'turn.end';      sessionId: string; result: IMLoopResult }
  | { kind: 'session.event'; sessionId: string; event: 'session.start'|'turn.end'|'session.end'; data: unknown }
  | { kind: 'memory.activity'; sessionId: string; activity: 'compress.started'|'compress.done'|'m3.archived'|...; detail?: unknown }
  | { kind: 'log'; level: string; msg: string; fields?: Record<string,unknown>; ts: number; component?: string }
  // 未来：permission.changed / model.changed / workspace.* ...

export type GateRequest =                      // 请求-应答
  | { kind: 'approval'; requestId: string; payload: ApprovalRequest }
  | { kind: 'ask_user'; requestId: string; payload: { questions: AskQuestion[] } }

export type GateCommand =                      // 入站
  | { kind: 'user.prompt'; sessionId: string; text: string }
  | { kind: 'session.create'; payload: { title?: string; workDir?: string; workingAgentId?: string } }
  | { kind: 'session.open' | 'session.close' | 'session.delete'; sessionId: string }
  | { kind: 'session.list' }
  | { kind: 'turn.cancel'; sessionId: string }
  | { kind: 'approval.decision'; requestId: string; decision: 'approved'|'rejected' }
  | { kind: 'ask_user.answer'; requestId: string; answers: unknown; cancelled?: boolean }
  | { kind: 'permission.revoke' } | { kind: 'permission.full'; enabled: boolean }
  | { kind: 'artifact.get'; artifactId: string }   // 拉 HTML

export interface SignalGate {
  emit(sig: GateSignal): void
  on(kind: GateSignal['kind'], cb: (sig: GateSignal) => void): () => void
  request(req: GateRequest): Promise<unknown>          // 挂起等 resolve，带超时 fail-closed
  resolve(requestId: string, payload: unknown): void
  command(cmd: GateCommand): Promise<unknown>          // 入站，路由到执行器
  snapshot?(): GateSnapshot                            // 供 Web 层 REST 兜底
}
export function createSignalGate(opts?: {
  logger?: Logger
  approvalTimeoutMs?: number      // 默认 300_000，对齐 approval-hook
  handlers: {                     // 入站命令执行器（依赖注入，Gate 不 import im）
    runPrompt(sessionId: string, text: string): Promise<IMLoopResult>
    session: SessionManager
    cancel(sessionId: string): void
    revokeAll(): void
    setFullPermission(enabled: boolean): void
  }
}): SignalGate
```

### 5.2 接线器 — `src/signals/wiring/`（新增，把状态机挂点接进 Gate）

每个接线器 = 一个小函数，subscribe 到既有机制 → Gate.emit / 把 handler 换成 Gate 请求。**放在 signals 侧，不改 im 源码**（除 call.ts delta + approval handler 两处）。

```
src/signals/wiring/
  hook-system.ts     // HookSystem(SessionStart/TurnEnd/SessionEnd/PostToolUse) → session.event
  loop-hooks.ts      // afterToolExecution 转发 tool 轨迹 → tool.started/result；afterShellCall → turn.end
  rendering.ts       // 订阅 RenderingSignalBus → emit artifact（渲染基座先给 Gate）
  state-line.ts      // StateLine.subscribe + drive-coordinator systemSend 截获 → memory.activity
  delta-bridge.ts    // call.ts onStreamChunk → assistant.delta/thinking.delta/tool.started
  log-sink.ts        // logger.setSink → emit log（全局，不限 session）
  approval.ts        // 把 approvalHandler（extensions 默认 stub）替换为 gate.request('approval')
  ask-user.ts        // requestHandler('request_user_input') → gate.request('ask_user')
```

### 5.4 Web 服务层 — `src/webshell/`（新增）

**同一 node:http server 按路径分派**（官方 deepseek host-webserver + host-frontend-static 模式，§7 #3）：
- `/api/v1/cmd`（REST 指令）、`/api/v1/snapshot`（全量重拉兜底）→ HTTP
- `/api/v1/ws`（事件流）→ **`server.on('upgrade')` 交给 `ws` 的 WebSocketServer**（官方同款：upgrade 路由表按 pathname 查，命中才握手，否则 destroy）
- 其余路径（非 /api）→ **静态 fallback**：serve dist SPA（index 需过鉴权，资产公开，路径穿越 403）——v0.22 webapp 构建产物
- `/healthz` 豁免鉴权

```
src/webshell/
  server.ts    // createWebShellServer({ gate, distDir?, host?, port? })
               //   node:http + ws@8；同端口：/api/v1/cmd + /api/v1/snapshot + /api/v1/ws + 静态 fallback + /healthz
  auth.ts      // bearer token: randomBytes(32).base64url、0600 文件、token 放 URL fragment
               //   REST 走 Authorization 头；WS 借子协议头（浏览器 WS 无法设 Authorization）；/healthz+静态资产豁免，index 过鉴权
  stream.ts    // 事件流：订阅 gate.on(*) → 转 WS 帧；内存 seq 游标（每连接/会话），断线带游标重连
               //   服务端内存 ring buffer 补发；越界/不足 → 发 resync → 前端走 /api/v1/snapshot 全量重拉（不落盘 journal，§7 #2）
  index.ts
```
Web 层订阅 `gate.on(*)` → 转 WS 帧；收 WS/REST 指令 → `gate.command(cmd)`。**Web 层不含业务，只翻译。** 依赖：仅 `ws`（见 §7 #1），HTTP 用 node:http。

## 7. 决策信息（Decisions）

**已决定（2026-09-06，三项均经官方 deepseek harness 源码实证后拍板）**：
- Signal Gate 与 Web 层分开；Gate 纯内存可独立测试；Web 层只是通道之一（§4 原则 1）。
- 本计划不含任何前端；v0.22 才是前端 UI（独立计划）。
- 渲染基座先给 Gate 再转基座；基座内部实现不变。
- 审批不新增机制，把 extensions.ts stub 换成 Gate handler。
- 日志出站：`logger.setSink` → Gate.emit('log') → 前端（渲染在 v0.22）。便于用户审查。
- **WS 用 `ws@8` 库**（§5.4）：官方 dsh 家族 3 个承担 WS 的包（`dsh` / `dsh-api-gateway` / `dsh-web-frontend`）全部依赖 `ws: 8.21.0`，kimi kap-server 亦用 `ws`。理由：WS 是帧协议（握手/掩码/分片/ping-pong/关闭），手写正确覆盖所有边界成本与成熟库同阶。`ws` 只进 `src/webshell/`（应用侧），**库核心保持零外部依赖**。
- **断线恢复 = 内存 seq 游标 + 越界全量重拉，不落盘 journal**（§5.4）：官方 api-gateway 的流协议是"快照基线 + 游标续增量"（`journal-stream.d.ts`：`{opened, cursor, page}` + `{entry}`，`replace/prepend/append` 三类变更带 hasMore）；但那是远程 Host↔Client。**本机 UI**（127.0.0.1）官方没有持久 journal——本机断线罕见、重连快，官方/kimi 都指向"游标续增量，越界/积压超限就 resync → REST 全量重拉"。采纳该模型，只做内存态 seq 游标 + 服务端短 ring buffer，不落盘。
- **静态托管同端口分派**（§5.4）：官方拆两包但同一 server——`host-webserver` 用 `node:http.createServer` + `server.on('upgrade')` 按 pathname 查 upgrade 路由表（api-gateway 的 `/api/remote.mux` 注册于此），自己不 serve 文件（"composing application owns dist serving"）；`host-frontend-static` 挂在 webserver 的 fallback seat 上 serve dist。**结论：同端口、同 server、按路径分派**（/api → HTTP、/upgrade → WS、其余 → 静态 fallback）。index 需过鉴权，非 index 资产公开（token 在 fragment，页面无密）。

**不再有未决项**（原 §7 三个"待用户拍板"均经官方实证后由用户拍板为上述决定）。实现时如遇 ws 握手/鉴权细节与官方不一致，以官方 `dsh-host-webserver` / `dsh-api-gateway` / `dsh-host-frontend-static` 源码（`本地对标仓库` 下 tarball）为参照。
