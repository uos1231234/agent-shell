## 1. 约束（Constraints）

1. **核心哲学第 6 条**：hook/设置入口是 harness 自身的信息流接缝，不是第三方插件 API。设置菜单只暴露 harness 自己的功能开关，不做插件市场。
2. **前端与状态机之间只有信号关系**（v0.21 拍板）：设置面板的读写必须走 Gate 命令（REST /api/v1/cmd），前端不直接读写 providers.json。
3. **ADR-018 D6 注册无热插拔**：MCP/skill 注册是启动期行为。设置面板对 MCP/Skill 的管理（后续阶段）做"编辑配置 + 重启提示"，不做运行期热插拔。
4. **ADR-015**：不新增 guard/metric/config 字段。`promptInjectionDefense` 是 buildStaticPrompt 的函数参数，不进 ShellConfig。
5. **v0.22 拍板**：webapp 独立目录同仓；前端类型唯一来源 = 库的 src/signals（import type，编译期擦除）。
6. **用户提供的设计参考**：设置按钮在**左下角**（参考 Codex 前端 + 用户提供图片的底栏形态：头像/用户名/标签 + 齿轮图标）；设置菜单栏目里应包含服务商管理、MCP 管理、Skill 管理、用户创建子代理。

## 4. 设计原则（Principles）

1. **文件为事实源，前端只是编辑器**：providers.json 是唯一事实源；前端 CRUD 经 Gate 写文件，不缓存第二份真相。
2. **写文件必须原子 + 备份**：write.ts 用 tmp + rename 原子写，写前落 `.bak`。
3. **写入前必须校验**：复用 load.ts 的 validateShape/validateProvider（导出复用），坏数据写不进文件。
4. **激活即写文件，生效需重启**：active 切换立即写文件；生效时机 = 下次 web-host 启动（当前会话不变）。UI 提示"重启 web-host 后生效"。
5. **MCP/Skill/子代理占位**：数据源（web-host 装配 MCP/skill/子代理）尚未存在，做列表接口返回空集不如占位诚实。占位 tab 说明"将在后续版本提供"。
6. **不新增 guard/metric/config 字段**（ADR-015）：promptInjectionDefense 是函数参数，不进 ShellConfig。
